# M13b1 Tags Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SketchUp tags: named, colored, show/hide-able tags on edges, faces, instances and guides; hidden tags hide what they tag (drawing, picking, inference); a Tags panel, Entity Info tag field and "color by tag" view; tags in `.skr`, commands, queries, and carried through `.skp` import and export.

**Architecture:** Tags live in the scene like materials: a `Tag { name, color, visible }` table keyed by `TagId` (serialized `t<n>`, from the scene's id counter), changed by undoable scene steps. Edges, faces, instances and guides gain `tag: Option<TagId>` (None = Untagged), carried by the existing per-entity ops. A single visibility predicate (an entity is visible when its own tag and, for nested geometry, every enclosing instance's tag are visible) is used by the renderer, picking, inference and the outliner. `.skr` gains the table and per-entity tags (schema 10; older files load untagged). The `.skp` importer maps layers to tags (and their visibility and colour) instead of warning; the writer writes tags as layers.

**Tech Stack:** Rust 2024, egui 0.36.2, wgpu 30. No new dependencies.

**Spec:** `docs/superpowers/roadmap.md` row M13b (split: M13b1 tags, M13b2 scenes).

## Global Constraints

- No new dependencies. Existing behaviour unchanged for untagged models (everything Untagged and visible); golden images unchanged.
- Tag names: non-blank, at most 256 characters, unique among tags (case-sensitive, as material names); "Untagged" is reserved (it is the absence of a tag).
- `.skr` schema 10; files of schema 9 and older open untagged; a file with an unknown tag id on an entity is refused.
- New command variants get arms in `Document::execute`/`edit` and `session::batch::id_slots` (no `_` arm); new id-bearing fields that hold a `TagId` are reference keys only if refs support `t` (they do not: tags are not referenceable in batches in this milestone; the drift test must still pass).
- Gate per task: fmt, clippy `-D warnings`, `cargo test --workspace`, and `cargo clippy --workspace --all-targets --target x86_64-pc-windows-msvc -- -D warnings`; CI on push. `export PATH="$HOME/.cargo/bin:$PATH"`.
- Docs updated in the task that changes behaviour. No emoji. Short commit messages, no attribution lines. Never `git add -A`.

## Spec notes (rulings)

1. **Model:** `kernel::TagId(u64)` (`"t<n>"`, schema `^t(0|[1-9][0-9]*)$`), `kernel::Tag { name: String, color: [u8; 3], visible: bool }`, `Scene::tags()`, scene steps `AddTag/RemoveTag/ChangeTag` (undoable like materials). `Edge`, `Face`, `Instance` and `Guide` gain `tag: Option<TagId>` (serde default, skipped when None). Splits, copies, explode, make_group and the stencil paths carry an entity's tag like its material (edges split keep the tag; copies keep it; exploded geometry keeps its own tag, or takes the instance's tag when it had none — SketchUp's rule).
2. **Commands:** `add_tag {name?, color?}` (name default "Tag", "Tag 2", ...; color default from a fixed palette of 12 distinct colors in order); `change_tag {tag, name?, color?, visible?}`; `delete_tag {tag, move_to?}` (entities on it move to `move_to` or Untagged, in one undo step); `set_tag {ids, tag}` (`tag` null = Untagged; vertices are refused; one undo step). Visibility changes are undoable steps (SketchUp makes them non-undoable; we keep one rule for all model changes) and mark the model modified.
3. **Queries:** `tags` → `[{id, name, color, visible, count}]` (count = entities in the whole model carrying it); entity info results gain `tag` (id or null).
4. **Visibility:** `pub fn is_shown(scene, path: &[InstanceId], tag: Option<TagId>) -> bool` (kernel or render, one place): hidden when the entity's tag is hidden or any instance on its path has a hidden tag. Used by the renderer (faces, edges, guides, instances), picking (`pick`, `pick_box`), inference snapping, the outliner (hidden rows greyed, still listed), Zoom Extents (ignores hidden geometry), and export (OBJ/STL/glTF export only shown geometry; `.skp` export writes everything with its tag).
5. **Color by tag:** a view setting `set_color_by_tag {on}` (saved with the camera like lighting; not an undo step): faces drawn in their tag's color (Untagged keeps materials); edges keep their style.
6. **Window:** a "Tags" tab in the right dock: rows with a visibility eye, color swatch (click to pick), name (double-click to rename), entity count; "+" adds, "-" deletes (asks where entities go when the tag is used); a "Color by tag" toggle at the top. Entity Info shows and edits the selection's tag (a combo: Untagged + tags; mixed selection shows "Mixed").
7. **`.skp`:** import maps the file's layers to tags (name, color, visibility; Layer0 → Untagged; names made unique) and each entity's layer to its tag; the "tags were not imported" warning goes away. Export writes each used tag as a `CLayer` (name, color, hidden flag) and each entity's drawbase layer slot (ports openskp's layer writing; `skpwrite` gains `Doc::tags` and per-entity `tag: Option<usize>`); round trip keeps tags.

## Review Focus

1. Undo of `delete_tag` restores the tag and every entity's tag; redo moves them again.
2. A hidden tag on a group hides everything inside it, including geometry tagged with a visible tag; picking and inference ignore it.
3. Copy, explode, make_group and edge splits keep tags as ruling 1 says.
4. Opening an old `.skr` gives an untagged model; save then reopen keeps tags, colors and visibility.
5. A `.skp` with hidden layers imports with those tags hidden, and exporting then reimporting keeps tags and visibility.
