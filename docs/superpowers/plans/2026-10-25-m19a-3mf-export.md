# M19a 3MF Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export the model, or the selection, as a 3MF package for 3D printers and slicers: one object per root part, millimeters, part names, material colors, and a closed-mesh check per object.

**Architecture:** A kernel `Scene::triangles_by_part` groups the shown triangles by root part (each root instance with its subtree and world transform baked in, loose root faces as one more), optionally limited to a selection. A session `threemf.rs` welds each part's triangles into an indexed mesh, checks it, and writes the OPC package (`[Content_Types].xml`, `_rels/.rels`, `3D/3dmodel.model`) with the `zip` crate. `ExportFormat::ThreeMf` goes through `export` and `export_bytes`; the report lists the objects.

**Tech Stack:** Rust 2024. Runtime: no new dependencies. Tests: `quick-xml` (MIT, already in the lock file) as a dev-dependency of `session`, to parse the package back.

**Spec:** `docs/superpowers/roadmap.md` row M19a; 3MF Core Specification 1.3.

## Spec notes (rulings)

1. **Parts.** One `<object type="model">` per shown root instance (group or component), named after its definition, with every nested instance baked in. Loose root faces become one more object named "Loose geometry". Hidden instances and faces, and hidden tags, are left out as for the other formats. Instances are never shared between build items: each placement of a component is its own object with its world transform baked into the vertices, which every slicer reads.
2. **Units and axes.** `unit="millimeter"`; coordinates are the model's (Z up, as 3MF is) times 1000.
3. **Meshes.** Vertices are welded within each object (positions equal to a nanometer), so the mesh is indexed; triangles that collapse to a line are dropped.
4. **Closed check.** An object is closed when every directed edge of its triangles occurs once and its reverse once, and its signed volume is positive (faces point outward). `ExportReport.objects` lists, per object, `name`, `vertices`, `triangles`, `closed` and, when not closed, `why`. `warnings` names the open objects.
5. **Colors.** The front material of each triangle: a `<basematerials>` group holds each used material (name, `displaycolor` `#RRGGBBAA`, alpha from opacity; the default material when a triangle has none), triangles carry `pid`/`p1`. Textures are not written; their base color is.
6. **Selection.** `export` takes `selection: true` (3MF only): only the selected root instances and the selected loose faces. It needs the root as open context and a selection that yields triangles.
7. **Package.** Deflated zip, `[Content_Types].xml` first. Names are XML-escaped.
