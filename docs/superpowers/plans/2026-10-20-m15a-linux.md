# M15a Linux Build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The window app, headless mode and the MCP server build, test and run on Linux (x86_64 and aarch64), with Linux-standard file locations, documented system packages, and a CI that builds and tests every push on Linux.

**Architecture:** A small `paths` module in the app crate decides where prefs, recovery files and the default agent socket live, per platform (macOS unchanged; Linux by the XDG base directory rules, with a one-time read of old `~/.tenon` prefs). Keyboard handling stops treating the Super key as Cmd off macOS. A Docker script runs the whole build and test suite in a Linux container (software Vulkan through Mesa lavapipe, so GPU tests run), and the same steps run in GitHub Actions.

**Tech Stack:** Rust 2024, winit 0.30.13, wgpu 30, rfd 0.17.2 (xdg-desktop-portal, zenity fallback), Docker, GitHub Actions. No new crates.

**Spec:** `docs/superpowers/roadmap.md` row M15a.

## Global Constraints

- No new crates. macOS behaviour and file locations are unchanged.
- Linux file locations follow the XDG Base Directory spec: an `XDG_*` variable is used only when it is set to an absolute path; otherwise its default under `HOME`.
- Private files and folders keep the existing protections (0700 folders, 0600 files, symlink refusal) on Linux.
- CI runs on pushes to `dev` and `main` and on pull requests; Linux only (macOS runners cost ten times as much); jobs: fmt, clippy `-D warnings`, `cargo test --workspace` on `ubuntu-24.04` (x86_64) and `ubuntu-24.04-arm` (aarch64), with Mesa lavapipe installed so wgpu finds a software Vulkan adapter.
- Gate per task: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` on macOS, plus the Linux container run from Task 2 once it exists. `export PATH="$HOME/.cargo/bin:$PATH"`.
- Docs updated in the task that changes behaviour. No emoji. Short commit messages, no attribution lines. Never `git add -A`.

## Spec notes (rulings)

1. **Paths** (`crates/app/src/paths.rs`): `pub struct Paths { pub prefs: PathBuf, pub recovery: PathBuf, pub socket_dir: PathBuf }` built by `pub fn resolve(os: Os, env: &dyn Fn(&str) -> Option<OsString>, pid: u32) -> Option<Paths>` (`Os::{MacOs, Linux, Other}`; tests pass a fake environment). macOS: today's layout (`~/.tenon/prefs.json`, `~/.tenon/recovery`, socket by today's `choose_socket`). Linux: prefs `$XDG_CONFIG_HOME/tenon/prefs.json` (default `~/.config`), recovery `$XDG_STATE_HOME/tenon/recovery` (default `~/.local/state`), default socket `$XDG_RUNTIME_DIR/tenon-<pid>.sock` when `XDG_RUNTIME_DIR` is absolute, a directory owned by the user and not group- or world-writable, else today's fallback (`~/.tenon`). No `HOME` or an unusable `HOME`: as today (warning, no prefs, no recovery). `Other` (Windows, until M15b): today's layout.
2. **Old prefs:** on Linux, when the new prefs file does not exist and `~/.tenon/prefs.json` does, the old file is read once (the next save writes the new location); the old file is left in place. Recovery files already in `~/.tenon/recovery` are not moved; the docs say where they are.
3. **Keys:** off macOS, the command key is Ctrl only (`app.rs` sites that use `super_key() || control_key()`, and `is_fly_move`); on macOS unchanged (Cmd, with Ctrl as today where it already counts).
4. **Dialogs:** keep rfd's default xdg-desktop-portal backend with its zenity fallback; no GTK build dependency. If neither the portal nor zenity is available, the dialog's error is shown in the status line instead of failing silently (check what rfd returns and handle it).
5. **Linux container run** (`scripts/linux-test.sh`): builds a Docker image from `scripts/linux.Dockerfile` (Debian or Ubuntu with rustup pinned to the toolchain in use, `mesa-vulkan-drivers`, `libvulkan1`, `libxkbcommon0`, `libwayland-client0`, `libx11-6`, `libxcursor1`, `libxrandr2`, `libxi6`, `zenity` not needed for tests) and runs fmt, clippy and the tests with the repo mounted and a separate `CARGO_TARGET_DIR` in a Docker volume. Golden-image tests must pass under lavapipe; if they exceed the tolerance, the task records the measured differences and either regenerates nothing and raises the tolerance only for software adapters (documented) or skips goldens on software adapters with a printed note — the task picks one and says why.
6. **Docs:** `docs/linux.md`: build packages (none beyond a Rust toolchain and a C linker, per the dependency tree; verify), runtime packages for the window app (Vulkan or GL driver, xkbcommon, Wayland or X11 client libraries, xdg-desktop-portal or zenity for file dialogs), headless and MCP needing no display, file locations, how to run the container script. `docs/mcp.md`: Linux paths and the Claude Code setup (Claude Desktop has no Linux build). `docs/agent-api.md`: socket and recovery locations per platform.

## Review Focus

1. A `XDG_*` variable that is relative, empty or points at a non-private runtime dir must not be used (spec rule and the socket's safety).
2. Prefs migration must never overwrite or delete the old file and must not loop (read once, then saved to the new place).
3. Ctrl shortcuts must still work on Linux in-window menus and in `tool_input` (`ctrl` key events), and Super must not trigger commands.
4. The container script must not touch the host's `target/` (separate target dir) and must be runnable twice.
5. CI must not depend on secrets and must cache only the cargo registry and target dirs.
