# M20c glTF and COLLADA Import Limits Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lift the limits M19c left in the glTF and COLLADA importers: vertex colors become per-face materials, each texture reads the texture coordinate set it names, COLLADA colors are read in the file's color space, `KHR_texture_transform` is checked exact for everything a texture placement can express, and `EXT_meshopt_compression` and `KHR_draco_mesh_compression` files are decoded instead of refused.

**Architecture:** `SceneMesh` gains per-point `colors` (linear). A pass in `scene_read.rs` run by both readers turns each polygon's average corner color into a material variant of the polygon's own material (a copy with the color times the tint), made once per distinct color. A new `meshopt.rs` decodes the three meshopt bitstream modes and three filters from the Khronos extension text; `gltf_read.rs` decodes compressed buffer views up front into a map the accessor reader consults first, and decodes Draco primitives with `draco-core` into the same accessor-shaped vectors.

**Tech Stack:** Rust 2024. New dependency `draco-core` `=2.3.2` (Apache-2.0, pure Rust, `#![forbid(unsafe_code)]`, decoder feature only; its encoder feature is on in dev builds for fixtures). Dev-dependency `meshopt-rs` `=0.1.2` (MIT, pure Rust) to produce meshopt fixtures; the decoder itself is written from the published Khronos text.

## Spec notes (rulings)

1. **Vertex colors.** glTF `COLOR_0` (VEC3 or VEC4; float or normalized unsigned byte or short; linear) and COLLADA `COLOR` inputs (the lowest set). A polygon's color is the mean of its outer corners' colors, in linear light. A polygon whose material has no texture gets a variant of that material (or of a white default when it has none) with color = material color times that mean; named `<material> #rrggbb` (just `#rrggbb` without a material). Alpha is ignored. A polygon whose material has a texture keeps the texture (a per-face tint cannot be kept without copying the image), counted in a warning. Distinct variants are capped at 512 exact; past that each channel snaps to four levels (at most 64 more), so a gradient cannot flood the model with materials. Coplanar merging only joins faces of equal variant, so a colored surface keeps the face boundaries its colors draw.
2. **Texture coordinate sets.** glTF: a material's base-color texture reads `TEXCOORD_n` for the texture's `texCoord` (a `KHR_texture_transform` `texCoord` overrides it). A primitive lacking the set contributes zero coordinates (its faces take no placement) instead of dropping coordinates for the whole mesh. COLLADA: the diffuse `<texture texcoord="CHANNEL">` is looked up in the geometry instance's `<bind_vertex_input semantic=... input_semantic="TEXCOORD" input_set=...>`; without a binding the lowest set is read as before.
3. **KHR_texture_transform.** Applied per vertex (offset after rotation after scale, glTF's matrix) before placements are fitted, as M19c. Tests pin it exact for any offset, any rotation with equal scales, quarter turns with unequal scales, and a `texCoord` override. A transform a placement cannot hold (shear: a non-quarter rotation with unequal scales; or a mirror) still lays the nearest turn and scale with a warning; baking it into pixels would not stay exact under repeat, so that stays a known limit.
4. **COLLADA color space.** COLLADA does not declare one in its schema; `diffuse` and `COLOR` values are read as sRGB (SketchUp and most writers) unless the file says linear: an `<asset>` `<extra>` element named `color_space` (or `colorspace`) reading `linear`, or an authoring tool starting with `Blender` (whose exporter writes scene-linear values). Linear values are converted to sRGB for the model's colors.
5. **EXT_meshopt_compression.** Buffer views with the extension are decoded (modes ATTRIBUTES, TRIANGLES, INDICES; filters NONE, OCTAHEDRAL, QUATERNION, EXPONENTIAL) from the view's compressed range; the decoded bytes stand in for the view, with the extension's `byteStride`. A buffer with no URI that is not the `.glb` chunk, or marked `fallback`, is a placeholder: it holds no data and only the compressed views may name it. Sizes are bounded by the buffers' 128 MiB total and the point and polygon limits; a stream that is cut short, has a wrong header byte, or leaves bytes over is a `file` error. The extension is no longer refused.
6. **KHR_draco_mesh_compression.** A primitive with the extension is decoded by `draco-core` (triangle meshes only; point clouds and strips refused), under decode limits of the importer's point and polygon caps. The extension's `attributes` map semantic to Draco unique ids; values are read in the accessor's component type and normalization, so the primitive reads as an uncompressed one. Decoding errors are `file` errors naming the primitive.
7. **Unchanged.** Limits, side files, warnings, the window.

## Review Focus

1. The meshopt bitstream reading: block and group arithmetic, the triangle FIFOs, bounds on every read, no panics on hostile bytes.
2. Draco glue: attribute mapping by unique id, component conversion, limits before allocation.
3. Vertex color variants: material count caps, no change for files without colors, textured materials untouched.
4. Texture sets and COLLADA binding.
