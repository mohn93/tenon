# M8d Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drawing finds nearby edges and vertices through indexes (identical results, large copies and explodes near-linear), copy and context-import limits are raised, and deferred window and API polish is done; the remaining deferred items become a post-v1 backlog.

**Architecture:**
- Drawing a batch goes through `Nearby`: either a scan or log-structured `Index` levels over consecutive id ranges plus a short scanned tail of the newest ids; both return id-ordered supersets and the unchanged exact tests decide, so results never depend on which path ran.
- `Index` (BVH) gains loose builders (`of_points`, `of_segments`) whose ids are the caller's numbers, plus box, segment and early-exit plane queries; plane queries filter by segment ends at the leaves.
- `rebuild_plane_from` switches to indexed clearance and containment lookups above `MANY_PAIRS`; `draw_stencil` indexes its segments and new-face samples; both keep scan order.
- A `#[cfg(test)]` switch (`FORCE_INDEXES`) lets one test run every scenario both ways.
- Tools keep session settings in `tools::Remembered` (written on switch via `Tool::remember`, read by `ToolKind::make_with`); the editor owns it, plus import units and the last export format.
- The right panel scrolls as a whole only when shorter than 480 pt.
- Session direction inputs share `unit_vector`; the outliner query has an optional depth.

**Tech Stack:** Rust 2024; no dependency changes.

**Spec:** `docs/superpowers/specs/2026-10-10-tenon-design.md`: the milestone list (Task 3 adds the M8d line).

## Spec notes (rulings made in this plan)

- **Indexed neighbour search, exact results.** `insert_segment` (crossings, vertices along the
  segment) and `vertex_at` (split hit) get their candidates from `Nearby`: either the old full
  scan (`Nearby::Scan`) or indexes (`Nearby::Indexed`). Both hand back every edge/vertex that may
  be within `LENGTH_TOL`, in id order, and the same exact tests run on them in the same order, so
  faces, ids, change sets and undo are identical. A batch of at least `INDEXED_BATCH` = 8
  segments is indexed; smaller batches (`add_edge`, `add_polygon`, `add_curve`, push/pull, which
  draw segment by segment) keep scanning (cheaper than building an index).
- **Index levels.** Ids only grow, so the vertices/edges added during a batch are exactly the ids
  `>= mark`. `Nearby::Indexed` keeps a list of `Level`s, each an `Index` (points + segments) over
  a consecutive id range; ids past the last level (the "tail", at most `TAIL` = 256 ids, 4 in
  tests) are scanned. A new level is pushed when the tail passes `TAIL`; the last two levels are
  merged (rebuilt over their joint range) while the last is at least half the one before
  (Bentley-Saxe), so each id is indexed O(log n) times. Removed edges (split) are skipped by an
  existence check; edges never move during insertion.
- **Plane rebuild indexes.** `segments_near_plane`/`any_near_plane` test both segment ends
  against the plane (within 2 x `LENGTH_TOL`, a superset of the exact test) at the leaves,
  instead of returning every leaf shape. `rebuild_plane_from` uses indexes when
  regions x (edges + old faces) > `MANY_PAIRS` = 4096: `PlaneGraph::interior_point` finds the
  clearance from edges within 4e-4 x side length (only edges nearer than 2e-4 x side can shorten
  the step, so the step equals a full scan's), and the containing old face is looked up by the box
  over all its loops (a point outside a polygon's box is outside it, so `position` gives the same
  index).
- **Stencil post-processing indexes.** `draw_stencil` puts the copied segments in an index
  (positions as edge ids) for the "faces in a plane the drawing reaches" test and for
  `on_stencil`, and the new faces' sample points in an index (face ids as vertex ids) so each
  placed/before ring tests only faces whose sample lies in its box (padded by `RING_BOX_PAD` =
  1e-5). `own` and `split_off` become sets; orientation/paint is applied ring by ring in id order
  as before.
- **Differential checks.** In-tree: `edit::tests::drawing_with_the_index_gives_exactly_what_
  scanning_gives` forces both paths through `FORCE_INDEXES` (cfg(test) thread-local, also
  forcing `rebuild_plane_from`'s choice) on copies with openings, crossing circles, push/pull
  tubes, imports and explodes, and a line grid, comparing `SceneData` and every `SceneChange`, then
  undoing all. Out of tree (probe `scratchpad/probe_m8d.rs`, not committed): six scenarios
  (frame copies, tubes + rotated `copy_placed`, 12 circles copied, 12x12 terrain copies, 30x30
  terrain explode + copies, flat imports exploded onto a face and over each other, components
  copied and exploded) serialized at 05bb9d5 and at u1: byte-identical after stripping the
  HashMap-ordered lookup fields from `Debug` output (old run 17.4 s, new 1.7 s). Note: building
  the old commit in the shared target dir needs its sources touched, or it reuses new artifacts.
- **Limits raised.** `MAX_COPIES` 100 -> 1,000 (its original value, lowered in M4b only because
  copy was cubic). `MAX_CONTEXT_IMPORT_FACES` 2,000 -> 10,000 (not 20,000: a flat 20k-face import
  exploded onto a face takes 9.8 s release, 10k takes 3.6 s). No output-size guard on copies
  (deferred).
- **Timings (release, this machine; `cargo test --release -p kernel --test perf -- --ignored
  --nocapture`).** Copy an exploded 1,800-face terrain 3 times: 9.34 s -> 0.44-0.59 s. Explode a
  20,000-face import: 86.5 s -> 2.2-3.3 s. Explode a 1,800-face import: 0.77 s -> 0.11 s. Copy 30
  circles 3 times: 0.74 s -> 0.05-0.09 s. Copy 30 circles 100 times in one plane: 552 s -> 2.5 s.
  Probe only: 30 circles x 1,000 (30,030 faces in one plane) 32 s; 1,800 faces x 100 (181,800
  faces) 25 s (80 s with the first, single-index version). Edits inside a 20k-face group and
  drawing 30 circles one by one unchanged (0.1-130 ms; ~0.5 s). New ignored perf tests bound copy
  terrain < 3 s, explode 20k < 15 s, circles x100 < 10 s.
- **Session tool settings.** Tools write session settings into `tools::Remembered` (circle
  sides, arc segments) through `Tool::remember` when the editor switches tools;
  `ToolKind::make_with` starts the new tool with them. Reselecting the current tool keeps them.
  Not saved across runs.
- **Letter case.** `editor_key` makes an ASCII letter uppercase exactly when Shift is held (Caps
  Lock no longer turns "g" into "G"; Caps Lock + Shift gives "G" on every platform).
- **Held keys.** `Editor::key_repeat` ignores a repeated character while nothing is typed: tool
  letters, "g", Shift+G and Shift+Z act once per press; typed text still repeats.
- **Right panel scroll.** Below `PANEL_MIN_HEIGHT` = 480 pt the panel lays its contents out in a
  480 pt box inside a vertical `ScrollArea`; at or above it the layout is unchanged.
- **Import units.** File > Import Units (Meters, Centimeters, Millimeters, Inches, Feet) is an
  editor setting for the session (`ImportUnits`, default Meters) passed as the import command's
  `scale` (None for meters); the status names the units when not meters. No dialog.
- **Export suggestion.** rfd cannot report the chosen filter, so the dialog lists the format of
  the last successful export first and suggests its extension (`Editor::export_formats`, OBJ
  until something is exported).
- **Modifier docs.** Docs now say Cmd-click on macOS, Ctrl-click on Windows and Linux; the code
  still accepts either (Ctrl-click on macOS unverified on hardware).
- **Outliner depth.** `{"type": "outliner", "depth": n}` (`Query::Outliner { depth:
  Option<u32> }`): n levels below the root's instances (0 = root instances only); a node whose
  children were cut has `"truncated": true` and `children: []`. Absent depth = whole tree
  (unchanged output; `truncated` is skipped when false).
- **Directions.** `session::document::unit_vector` scales by the largest component before
  normalizing, so guide directions, rotate axes and circle/arc/rectangle normals of any finite,
  non-zero length are accepted (1e200 and 1e-300 were refused as "non-zero"; a 1e155 normal was
  asserted refused by `bad_circles_are_refused`, which now accepts it as a direction). Messages:
  "normal must be a finite, non-zero vector".
- **Camera action results.** `Editor::zoom_extents` / `standard_view` (via
  `run_camera_command`) return true only if the camera, the status message or the hover changed.
  The API results are unchanged (camera commands return empty changes).
- **Count messages.** Text ending in "s" that is not a valid count ("0s", "2.5s", "-3s", "s")
  gets "Sides must be a whole number from 3 to 360, like 24s" (Circle) or "Segments must be a
  whole number from 2 to 360, like 12s" (Arc) instead of a radius/length message.
