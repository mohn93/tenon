# M16b Autosave and Crash Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The open model is saved every N minutes (Settings) to the private recovery folder without touching the user's file; after a crash the next start offers to restore or discard it; normal save, new, open and close clean it up; the existing recovery-on-discard files appear in the same list (File > Recover Models...).

**Architecture:** A `recovery` module in the app crate owns the recovery folder: each window process holds an exclusive OS lock (`std::fs::File::try_lock`) on its own `session-<pid>-<unix secs>.lock` for its lifetime, and writes its autosave as `<stem>-<session>.autosave.skr` with a sidecar `<same>.json` (`{ "kind": "autosave" | "discarded", "original": path?, "saved": unix secs, "session": "<id>" }`). An entry whose session lock can be taken by another process belongs to a process that is gone (crash). The window schedules autosave ticks through the existing `about_to_wait` deadline mechanism and writes with `Document::write_copy` (synchronous). Headless and MCP modes never autosave (prefs and Settings are window chrome).

**Tech Stack:** Rust 2024 (toolchain 1.99; `File::lock`/`try_lock` are std), egui 0.36.2. No new dependencies.

**Spec:** `docs/superpowers/roadmap.md` row M16b.

## Global Constraints

- No new dependencies. Existing behaviour unchanged where not named here; golden images unchanged; `.skr` schema unchanged.
- Recovery files and sidecars are owner-only (`Access::Private` / `cli::ensure_private_dir` rules: 0700 folder, 0600 files, Windows owner-only ACLs); symlinks in the folder are never followed or listed.
- Never write to, move or delete the user's own file; only files inside the recovery folder are written or removed.
- Tests never use the real recovery folder (temp dirs per test, named by pid and test name).
- Gate per task: fmt, clippy `-D warnings`, `cargo test --workspace`, and `cargo clippy --workspace --all-targets --target x86_64-pc-windows-msvc -- -D warnings`; CI on push. `export PATH="$HOME/.cargo/bin:$PATH"`.

## Spec notes (rulings)

1. **Setting:** `Prefs.autosave_minutes: u32`, default 5, 0 = off, clamped to 0..=60 on load. Settings gets a "Files" tab with an "Autosave every" slider (0 shown as "Off", unit "min").
2. **When:** an autosave runs when autosave is on, the document is modified, its revision differs from the last autosaved revision, and the interval has passed since the later of the last autosave and the first unsaved change. It does not run while a tool operation is in progress (a drag or a multi-click tool mid-operation); it waits for the next frame where none is. A failed write shows a status message once per failure kind and retries at the next interval.
3. **Files:** one autosave file per process, overwritten in place with the private atomic replace; the sidecar is written after the model file. `<stem>` is the open file's stem (sanitized as `recovery_path` does) or "untitled". Discard-recovery files (agent `new`/`open`/`quit` with `discard`) keep their current names and get a sidecar of kind `discarded` with this session id.
4. **Clean-up:** the autosave file and sidecar are removed after a successful Save (window or agent), after New/Open replaced the document (once the unsaved prompt was settled), and on normal exit (`exiting`). Discarded files are never removed automatically.
5. **Liveness:** a session is live while its lock file is locked. At start a process creates and locks its own lock file; listing treats an entry as **crashed** when its session lock file is missing or can be locked (then immediately unlocked) by the lister. Lock files of dead sessions with no entries left are removed when listed.
6. **Recover window:** at start, if there are crashed autosaves, a "Recover Models" window opens automatically listing them (name, original path or "Untitled", time saved); File > Recover Models... opens the same window at any time and also lists discarded files. Each row: **Open** (settles unsaved changes first; opens the recovered model as an untitled modified document whose title shows `<name> (recovered)`; the recovered entry then becomes this session's autosave: its files are renamed under this session id so normal clean-up applies) and **Discard** (removes the entry's files after a confirmation). A "Discard All" button with confirmation. Entries of live sessions (another open window) are never listed.
7. **Agent API:** no new commands. Agent `save`/`new`/`open` trigger the clean-up of ruling 4 in the window; headless and MCP are unchanged. Docs describe autosave and the Recover window.

## Review Focus

1. Two app windows open at once: neither lists the other's autosave; killing one (no clean-up) makes its autosave appear in the other's File > Recover Models... list.
2. A crash during an autosave write (partial file) never leaves a corrupt entry listed as recoverable: entries whose model file fails to open are shown with an error and can only be discarded.
3. Save to the user's file, then crash: no stale autosave of the saved state is offered (clean-up on save), and the user's file was never touched by autosave.
4. Restoring an entry, then saving it, removes the recovered files; restoring then crashing again offers it again.
5. A symlink or a file with wrong permissions in the recovery folder is neither listed nor followed, and the folder check failing disables autosave with a status message instead of failing silently.
