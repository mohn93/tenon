# M13b2 Saved Scenes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SketchUp scenes: named saved views (camera, projection, lighting, color by tag, tag visibility) that the user adds, updates, renames, reorders, deletes and switches to from tabs above the viewport and a Scenes panel; in `.skr`, commands and queries; scenes read from `.skp` files and written to them.

**Architecture:** Scenes are model data, kept in the kernel `Scene` next to tags as an ordered list of `Page { id: PageId, name, view: Option<PageView>, tags: Option<BTreeSet<TagId>> /* hidden tags */ }` with undoable steps (`AddPage`, `RemovePage`, `ChangePage`, `MovePage`). `PageView` is plain data (eye, target, up, fov_y, parallel, night, color_by_tag) so the kernel needs no session types; the session converts to and from `Camera`/`Lighting`. Going to a scene (`go_to_scene`) is a view command: it sets the camera and view settings (not undoable, like `set_camera`) and, when the scene stores tag visibility, applies it as one undoable `change_tag` batch (tag visibility is model data since M13b1). `.skr` schema 11. The `.skp` reader already parses pages for 2021+ files (`crates/skp/src/pages.rs`); legacy files report scenes as not imported.

**Tech Stack:** Rust 2024, egui 0.36.2. No new dependencies.

**Spec:** `docs/superpowers/roadmap.md` row M13b2.

## Global Constraints

## Spec notes (rulings)

1. **Model:** `kernel::PageId`, `kernel::Page`, `kernel::PageView { eye: [f64;3], target: [f64;3], up: [f64;3], fov_y: f64, parallel: bool, night: bool, color_by_tag: bool }`, `Scene::pages()` (ordered). `view: None` means the scene does not change the camera or view settings; `tags: None` means it does not change tag visibility. Deleting a tag removes it from every page's hidden set in the same undo step. `Scene::validate` checks page tag ids exist and names are unique.
2. **Commands:** `add_scene {name?, camera?: bool (default true), tags?: bool (default true)}` stores the current view and/or the current hidden tags, appended last; `update_scene {scene, camera?, tags?}` re-stores what is asked (default: whatever the scene already stores); `change_scene {scene, name}`; `move_scene {scene, index}`; `delete_scene {scene}`; `go_to_scene {scene}`. All but `go_to_scene` are one undo step each and mark the model modified. `go_to_scene` sets the camera, projection, lighting and color by tag (no undo step, as `set_camera`), and applies tag visibility as one undo step labelled `go_to_scene` only when it changes something. The document remembers the selected scene (not saved; cleared by new/open; set by add/go).
3. **Queries:** `scenes` → `[{id, name, camera: bool, tags: bool, selected: bool}]`; `scene {scene}` → the stored view and hidden tag ids.
4. **Window:** scene tabs in a strip above the viewport (shown only when there are scenes; click = go to; double-click = rename inline; right-click menu: Update, Rename, Move Left, Move Right, Delete, Add Scene). A "Scenes" tab in the right dock lists scenes with Add (+), Delete (-), Update, up/down reorder, and checkboxes for what each scene stores (Camera, Tag visibility). View menu: "Add Scene", "Previous Scene" (Page Up), "Next Scene" (Page Down) — check those keys are free.
5. **Transitions:** none (cut straight to the scene; SketchUp's animated transition is a follow-up).
6. **`.skp` import:** 2021+ files: each page becomes a scene with its camera (when present; perspective/parallel and field of view from `pages.rs`) and its hidden layers mapped through the M13b1 layer-to-tag map; names made unique; the "scenes were not imported" warning goes away for these files. Legacy (2017-2020) files keep the warning (their pages are not read). The file's selected page is not applied on import (the import keeps the current camera; open of a `.skp` as a document uses the file's own camera as today).
7. **`.skp` export:** out of scope for this milestone (the writer does not write pages; the export report keeps "scenes were not written"). Recorded as a follow-up.

## Review Focus

1. Undo of `delete_scene` restores it at its position with its stored view and tags; undo of `delete_tag` restores the tag in every scene's hidden set.
2. A scene that stores only tags leaves the camera alone when gone to, and one that stores only the camera leaves tag visibility alone.
3. `go_to_scene` on a scene whose stored tags match the current visibility adds no undo step.
4. Save and reopen keep scenes, their order, names, stored views and hidden tags; a schema 10 file opens with no scenes.
5. Importing a `.skp` with scenes into a model that already has a scene with the same name gives unique names; the tutorial corpus file's scenes import with their hidden tags (`#[ignore]` corpus test).
