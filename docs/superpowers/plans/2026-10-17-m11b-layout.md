# M11b Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The window gets its new layout. The menus become one table that drives both egui menus and native macOS menus (`muda`), plus a Keyboard Shortcuts window. The tools move to a 44 pt icon rail on the left. A 36 pt context bar holds Undo/Redo, a breadcrumb of the open path, the group buttons that apply, the day/night toggle and the agents indicator. The right side becomes a resizable dock with Entity Info and Materials tabs over an Outliner with a filter, split by a draggable divider, with its width, split and tab saved in prefs. Materials become a swatch grid where a click chooses without switching tool. The status bar is 28 pt with a 180 pt measurements box.

**Architecture:**
- `app/src/menus.rs` (new): the menu bar as data (`Menu`, `Entry`, `Item`), built from `View` and the shortcut table. `ui/menu_bar.rs` (new) draws it as egui menus. `app/src/native_menu.rs` (new, macOS only) builds the same data as a `muda` menu bar and keeps it in sync. On macOS the window key path leaves every Cmd chord to the native menu (`shortcuts::window_command`).
- `ui/rail.rs` (new): the tool rail. `ui/toolbar.rs` becomes `ui/context_bar.rs`. `ui/status.rs` is rewritten. `ui/dock.rs` (new) holds `DockLayout`, the dock, its tabs and the divider, and replaces the measured layout in `right.rs`. `right.rs` keeps Entity Info only. `materials.rs` becomes a grid, and `outliner.rs` gains a filter.
- `app.rs`: the `ApiWake` user event becomes `AppEvent { Api, Menu { id, repeat } }`. New actions: `Quit`, `ShowShortcuts`, `SetDock`, `PaintWithMaterial`. `Prefs` gains `dock`.
- The renderer, `session`, `api` and headless mode are not touched.

**Tech Stack:** Rust 2024; egui, egui-winit, egui-wgpu, egui_kittest `=0.36.2`; wgpu `=30.0.1`; egui-phosphor `=0.14.0`; winit `=0.30.13`; new: `muda =0.21.2` (Apache-2.0 OR MIT, `default-features = false`, macOS only; checked: depends on `objc2 ^0.6.1` (the tree already has 0.6.5) and `objc2-app-kit ^0.3`, dev-depends on `winit ^0.30`, and a scratch crate with it and winit 0.30.13 builds on this Mac). `objc2-app-kit =0.3.2` (already in the lock through rfd and muda) becomes a direct macOS dependency for the menu event's key-repeat check.

## Review Focus

- **A Cmd chord fires twice, or not at all, on macOS.** The native menu and the key path must not both act. Cmd+Z typed into a text field must reach the field, not undo the model, and a held Cmd+S must save once while a held Cmd+Z repeats. Task 9 tests: `with_native_menus_the_key_path_leaves_cmd_chords_to_the_menu`, `every_cmd_chord_is_a_native_menu_accelerator`, `undo_and_redo_menu_items_are_off_while_typing`, `held_keys_repeat_only_undo_and_redo_through_the_menu`.
- **A prefs file from M11a, or one with bad dock values.** A file with only `theme` keeps its theme and gets the default dock. Out-of-range values (width 9000, split -3) are clamped. A wrong type makes the file invalid, which gives the defaults and a warning as in M11a. Task 6 test: `dock_prefs_load_old_files_and_clamp_bad_values`.
- **The smallest window with a deep path, long names and 40 materials.** At 960 x 600 the context bar stays one row, with the right-hand group visible and the oldest crumbs folded into an ellipsis. The rail does not wrap, the Outliner keeps its least area, and the 3D view stays usable. Tests: `a_deep_path_folds_the_oldest_crumbs` and `the_context_bar_is_one_row_at_960` (Task 4); `the_panels_fit_the_smallest_window` (Task 6).
- **Choosing a material in the middle of a drawing operation.** The tool and its operation (the first corner of a rectangle, say) are kept. Add keeps the tool too. Only a double-click or the Paint tool paints. Task 7 test: `choosing_a_material_keeps_the_tool_and_its_operation`.
- **Resizing the dock or the divider.** Each produces one `SetDock` on release: none per drag frame, none at start, none from a window resize. The window can still go idle. Task 6 tests: `the_dock_reports_its_width_once_on_release`, `the_panels_settle_in_one_frame`.

## Spec notes (rulings made in this plan)

- **muda.** `muda = { version = "=0.21.2", default-features = false }`. The default `gtk3` feature is off, and muda is a `[target.'cfg(target_os = "macos")'.dependencies]` entry, so Linux needs no GTK. Accelerators use `Modifiers::META` (`SUPER` is deprecated in 0.21) and `Accelerator::new(mods, code)`, where `mods` is not an `Option`. The menu is built and `init_for_nsapp` is called in the first `render` (the app is running by then). `main.rs` keeps `with_default_menu(false)`.
- **Native accelerators are the Cmd chords only.** That is New, Open, Save, Save As, Import, Export, Quit, Undo and Redo. A plain-key equivalent in an AppKit menu would fire while a person types in a text field, so tools, G, Shift+G, Delete, Esc, Shift+Z and F are not native accelerators. Their native items show no key. Their keys appear in the rail tooltips, the egui menus and the Keyboard Shortcuts window. These keys stay on the editor's key path on every system.
- **No double fire.** On macOS, `shortcuts::window_command(.., native_menus: true)` returns `None` for every chord, because the menu bar handles them all (a test checks every Cmd chord in `TABLE` is a native accelerator). The native Undo and Redo items are disabled while a text field has focus, and their menu events are ignored then, so Cmd+Z goes to the field. A menu event raised by a held key (`NSApp.currentEvent.isARepeat`) is dropped unless its binding repeats (Undo, Redo). That keeps M11a's rule that a held Cmd+S saves once. A disabled native item's chord (Undo with nothing to undo) does nothing; M11a's "nothing to undo" status message now shows only off macOS. Other systems keep today's key path.
- **App menu (macOS):** About tenon (muda's predefined About with the name and `CARGO_PKG_VERSION`), a separator, Hide, Hide Others and Show All (predefined), a separator, then Quit from the table (`UiAction::Quit`, so the unsaved-changes prompt runs). Settings... is left out until M11e. Other systems have no app menu; Quit is the last File item, after a separator.
- **Menu layout and labels** (Title Case, one table). Native menus show the same entries:
  - File: New, Open..., Save, Save As..., separator, Import..., Import Units ▸ (the five units, checked), Export....
  - Edit: `Undo <Step>` and `Redo <Step>` (just "Undo" or "Redo", disabled, when empty; the step comes from `context_bar::step_name`), separator, Erase (Delete; needs a selection), Delete Guides (needs guides), separator, Soften Edges....
  - Draw: Line, Rectangle, Circle, Arc.
  - Tools: Select, Push/Pull, Move, Rotate, Tape Measure, Erase, Paint.
  - Group: Make Group, Make Component (both need a selection), Explode (needs a selected instance), Close Group (needs an open instance).
  - Camera: Zoom Extents, separator, the seven standard views, separator, Perspective and Parallel Projection (checked), separator, Night Lighting (checked), separator, Fly Mode (checked, with `FLY_HELP` as its egui tooltip).
  - View: Theme ▸ (System, Dark, Light, checked), Agent Activity.
  - Help: Keyboard Shortcuts.
  Checked items draw in egui as selectable buttons (AccessKit `toggled`) and natively as `CheckMenuItem`s. Menu item ids (native) are the item action's `Debug` text, for example `Tool(Line)` or `SetTheme(Dark)`.
- **Egui menus** sit at the left of the context bar when `View::egui_menus` is set. The app sets it to `!cfg!(target_os = "macos")`; the test fixture always sets it, so the table's egui form is tested on every system.
- **Keyboard Shortcuts window:** a non-modal egui window titled "Keyboard Shortcuts", opened from Help, closed by its close button (`UiAction::ShowShortcuts(bool)`, window chrome). It lists every `TABLE` entry under Tools, File, Edit, Group and Camera, each as `Bound::label()` and its key chip. It has no key binding of its own.
- **Rail:** a `Panel::left` drawn after the top and bottom panels, so it runs between them. It is 44 pt wide and not resizable, with a 6 pt side margin around 32 x 32 buttons and 4 pt between buttons in a group. Between groups there is an 8 pt gap with a 1 px `border` line centered in it. The glyphs are 18 pt Phosphor regular: Select `CURSOR`, Erase `ERASER`, Paint `PAINT_BUCKET`, Line `LINE_SEGMENT`, Rectangle `RECTANGLE`, Circle `CIRCLE`, Arc `BEZIER_CURVE`, Push/Pull `ARROW_FAT_LINES_UP`, Move `ARROWS_OUT_CARDINAL`, Rotate `ARROW_CLOCKWISE`, Tape Measure `RULER`. Each button is named by its tool's label. The active tool's button has the accent fill and an `on_accent` glyph. The tooltip is `hint(label, Bound::Tool(kind))`.
- **Context bar**, from left to right: [egui menus] | Undo, Redo | breadcrumb ... [Make Group, Make Component, Explode] | Night Lighting toggle, Agent Activity indicator. The right-hand group is laid out first, right to left, and the breadcrumb takes the room left over.
  - The group buttons are icon buttons (`BOUNDING_BOX`, `CUBE`, `ARROWS_OUT`) named "Make Group", "Make Component" and "Explode". They are not drawn at all when they do not apply.
  - Close Group leaves the bar. It is in the Group menu, and the breadcrumb and Esc also close groups.
  - The day/night toggle is a selectable icon button named "Night Lighting". It is on at night, shows `MOON` at night and `SUN` by day, and a click asks for the other lighting.
  - The agents indicator is an icon button named "Agent Activity" (`ROBOT`). It shows the count in accent text beside the glyph when agents are connected, its tooltip reads "No agents connected", "1 agent connected" or "N agents connected", and a click opens Agent Activity.
- **Breadcrumb.** The crumbs are "Model" and then each open instance's name. The name is the definition's name, or "Group" for an unnamed group, without the Outliner's angle brackets (`outliner::display_name`). The crumbs are separated by `CARET_RIGHT` glyphs in secondary text.
  - Every crumb but the last is a button named `Go to <name>` that asks for `OpenPath(context[..k])`.
  - The last crumb is strong text named `Editing <name>` ("Editing Model" at the root) and does nothing.
  - These names keep the crumbs apart from the Outliner's "Model" row and its row names.
  - When the crumbs do not fit, the oldest crumbs after "Model" fold into one "…" label (named "Hidden levels", with a tooltip naming them), and the last crumb always shows. Names longer than 24 characters are cut with "…".
- **Status bar.** It is a `Panel::bottom` with an exact 28 pt height, and everything is vertically centered in one row.
  - From the left: the tool chip (`status.tool` on `bg_hover`, radius 4, named `Tool: <name>` so it does not clash with the rail button), the prompt in secondary text, the lock pill, then the message in `warn`.
  - The lock pill shows the lock text, colored for its axis at 20% fill with axis-colored text: red `#E5484D`, green `#30A46C`, blue `#3E63DD`, otherwise the accent.
  - From the right: the agents badge (`Agents: N`, only when N > 0, opens Agent Activity), the selection count (`N selected`, only when N > 0), then the measurements box.
  - The measurements box is 180 x 24 pt with radius 6 on `bg_raised`. Its label (`status.label`, or "Measurements" when empty) sits inside on the left in 11 pt secondary text, and the value is right-aligned in 13 pt JetBrains Mono. A 2 pt accent ring shows while typing (the value ends in `_`, as `Status::value` documents). The box is named by its label, and it is hidden in Select and while flying.
- **Dock.**
  - It is a `Panel::right("dock")`, resizable, with `default_size` from `View::dock.width` and `size_range(240.0..=420.0)`. egui keeps the live width.
  - The dock reports `UiAction::SetDock` with the new width (rounded to a whole point) only on a frame where the primary button is released and the width differs from `View::dock.width`. So it never reports at start or on a window resize (at the 960 pt minimum, a 420 pt dock still fits beside the rail).
  - The inside margin is 12 pt. At the top is a tab row of two selectable buttons, "Entity Info" and "Materials"; a click reports `SetDock` with that tab. Under it is the top area, a vertical `ScrollArea` with the tab's content. Next comes an 8 pt divider named "Resize Outliner" (`CursorIcon::ResizeVertical`), then the Outliner area.
  - The top area takes `split` of the height below the tab row, clamped so both areas keep at least 160 pt. Dragging the divider moves it live; the value lives in egui memory until release, when the dock reports `SetDock` with the new split (rounded to hundredths).
  - The layout `{width 280, split 0.55, tab Entity Info}` is saved in prefs as `"dock": {"width": 280.0, "split": 0.55, "tab": "entity_info"}`.
  - The Outliner filter text and the scroll positions are session-only egui memory.
  - The measured layout of M11a (`right::Measured`, `least_height`, `remember`, `MATERIAL_ROWS_*`) is deleted. The scroll areas replace it, and nothing calls `request_discard` any more.
- **Prefs.** `Prefs { theme, dock: DockLayout }`, with both fields `#[serde(default)]`. `load` clamps the dock (`DockLayout::clamped`). A missing `dock` gives the default. A wrong type is an invalid file, which gives the defaults and a warning, as in M11a. `Prefs` drops `Eq` (it holds floats). `UiAction::SetDock` applies only when the layout changed, then saves through the same `save_prefs` that View > Theme uses.
- **Materials grid.**
  - Tiles are 56 x 56 pt swatches with radius 4, an 11 pt name caption under each (secondary, cut with "…" to the tile width), and 8 pt gaps. The column count is `max(1, floor((width + 8) / 64))`: 3 at the narrowest dock, 4 at the default.
  - The first tile is Default. A tile is named by its material's name, and the chosen tile has the 2 pt accent ring and AccessKit `selected`.
  - A click reports `ChooseMaterial(id)`. A double-click reports `PaintWithMaterial(id)`, and that click reports nothing else.
  - Add and Delete sit in a row under the grid. Then, for a chosen non-default material, comes an "Edit material" section header with M11a's controls (name, palette, Opacity, Glow, Texture..., size). Default has no Edit section.
  - In the editor, `choose_material` and `add_material` no longer switch tool, and `paint_with(material)` chooses and selects Paint.
- **Outliner filter.**
  - A single-line text field named "Filter outliner" (hint "Filter") under the Outliner header. While it is non-empty, a "Clear filter" icon button (`X_CIRCLE`) shows beside it.
  - Matching is case-insensitive substring matching on `display_name`.
  - While the filter is active, the Model row always shows. A node shows when its own name matches or when its definition contains a match at any depth. Only shown children are drawn, and nodes with shown children draw expanded (state under a separate id, so the stored expansion is untouched).
  - "Contains a match" is memoized per definition (`Filter::new` walks each definition once), so cost is linear in definitions, not in instance paths.
  - At most 500 rows are drawn, and then a weak "More matches: refine the filter" line. With no match the area shows "No matches".
  - The filter is window chrome. An agent uses the `outliner` query.
- **Agent API parity.**
  - Rail tools → `set_tool`.
  - Breadcrumb → `open_path`.
  - Context bar group buttons → `make_group`, `make_component`, `explode`.
  - Day/night toggle → `set_lighting`.
  - Material click → `set_paint_material`, and double-click → `set_paint_material` then `set_tool` (`paint`). The docs row for `set_paint_material` loses "(the window's Materials list also switches to Paint)".
  - Menu items → the commands their actions already map to.
  - Window chrome (no command): the dock width, split and tab (prefs), the Outliner filter, the Keyboard Shortcuts window, Agent Activity, and native vs egui menus.
- **Tests.** Menus in tests are egui menus, opened with a new helper `click_menu(h, &["Edit", "Erase"])`. It clicks the menu titles and then the item that appeared when the last menu opened, since Tools > Line shares its name with the rail's Line button and Edit > Undo with the bar's Undo. Fixtures for the Materials tests set `dock.tab = DockTab::Materials`. The renderer is not touched, so the CLASSIC goldens cannot change; Task 11 checks that `crates/render` has no diff and runs the byte-identical golden check only if it does.

/// may share its name with a rail or bar button, so the item clicked is the node with that
/// name that was not there before the last menu opened.
pub(super) fn click_menu(h: &mut H, path: &[&str]) -> Vec<UiAction> {
    let (item, menus) = path.split_last().expect("a menu path");
    let (last, before) = menus.split_last().expect("a menu title");
    for m in before {
        click(h, m);
    }
    let there: Vec<Rect> = h.get_all_by_label(item).map(|n| n.rect()).collect();
    click(h, last);
