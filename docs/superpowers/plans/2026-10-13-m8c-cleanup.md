# M8c Correctness and Performance Clean-up Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deferred correctness and performance items are fixed: per-mesh adjacency indices and batch drawing make copies, groups and explodes near-linear; files reopen bit-identical with consistent id rules; exports refuse overflows and report skipped faces; test scratch paths no longer collide; small panics and id leaks are gone.

**Architecture:**
- The kernel's per-mesh lookups (vertex -> edges, vertex -> faces, vertex grid) live inside `Model` and are maintained only in `apply_op`, the single place every recorded or applied op passes, so undo/redo and `apply` keep them exact; `validate` cross-checks them.
- Bulk drawing goes through `draw_segments`: all segments are inserted (tracking which edges are new), then `create_faces` rebuilds each touched plane once, using an edge-only BVH to find a plane's edges when many planes are touched.
- The spatial `Index` is dropped only by ops that move or add/remove vertices, edges or faces.
- `draw_stencil` evaluates "is this new face inside that ring" with cached face samples and prepared rings.
- Files: exact float parsing via `serde_json/float_roundtrip`; id bounds (`< 2^53`, `next_id <= 2^53`) and global id uniqueness enforced in `from_data`/`Scene::validate`; `file::write` refuses unsavable ids.
- Export: `Scene::triangles_and_skipped` feeds `export::encode`, which now returns `Result`; the command result carries `ExportReport`.

**Tech Stack:** Rust 2024; the existing `serde_json` dependency gains the `float_roundtrip` feature (no new crate).

**Spec:** `docs/superpowers/specs/2026-10-10-tenon-design.md`: the milestone list (Task 4 adds the M8c line).

## Spec notes (rulings made in this plan)

- **Lookups kept in step, not rebuilt.** `Model` gains three private lookups maintained by
  `apply_op` (so recording, undo, redo and `apply` all keep them exact): vertex -> edges
  (`HashMap<VertexId, BTreeSet<EdgeId>>`), vertex -> faces (`HashMap<VertexId,
  BTreeSet<FaceId>>`, every loop vertex of the face) and a vertex grid (`HashMap<[i64; 3],
  Vec<VertexId>>`, cells of `VERTEX_CELL` = 1 mm). They are not part of `PartialEq` and not
  serialized; `from_parts` builds them. Empty sets/cells are removed, so `validate` can compare
  them with maps rebuilt from scratch: `Model::validate` checks them first ("the vertex grid /
  vertex-to-edge map / vertex-to-face map does not match ..."), which makes every existing test
  that validates after an edit a test of the lookups.
- **Lookup results keep the old order.** `edges_at` and `faces_at` return ids in id order,
  `edge_between` the lowest matching id, `find_vertex` the lowest id within `LENGTH_TOL`
  (`vertices_near` sorts) — the same results the old full scans gave, so face creation order and
  ids do not change.
- **Copies are drawn as one batch.** `draw_stencil` (copy, copy_placed, make_group, explode,
  group duplication) inserts all its segments first (`draw_segments`) and then rebuilds the faces
  of each plane the new edges reach once. "New edges" are the edges the segments created plus the
  pieces of those edges a later segment split (tracked in a `fresh` set threaded through
  `insert_segment`/`vertex_at`/`split_edge`); pieces of pre-existing edges are not new, as
  before. Drawn one by one, a region closed by an earlier segment of the same batch counted as an
  existing face for later segments; in a batch it does not. That only matters inside an opening
  (the "apart" rule), and `draw_stencil`'s own orientation, paint and extra-face clean-up run
  after it either way; the whole suite and a batch-versus-one-by-one test (crossing lines,
  overlapping squares, a square across a face, a circle in a face, a square in an opening) give
  the same faces. `add_edge`, `add_polygon`, `add_curve` and push/pull still draw segment by
  segment (unchanged behaviour).
- **One plane, one rebuild.** `create_faces` first collects its candidate planes in first-seen
  order in a `PlaneSet` (a grid over normal and offset, 1e-3 cells, looking in every cell within
  twice the `same_as` tolerances, both orientations) instead of a linear `done` list, then
  rebuilds each. Faces are only added, removed or replaced while rebuilding, so above
  `FEW_PLANES` = 4 planes it finds each plane's edges with an edge-only BVH
  (`Index::of_edges` + `segments_near_plane`, then the exact `plane.contains` test, sorted by
  id); at 4 or fewer it scans as before. Old faces of the plane are the in-plane faces at those
  edges' vertices (drawing never leaves a face without its side edges). `rebuild_plane` called
  from erase, weld and the stencil "close it" step keeps the full face scan: after erasing or
  welding a face in the plane can have lost every edge (caught by the api push/pull-flush test).
  The new-edge side set is built once per `create_faces`, not once per plane.
- **Index survives non-geometry ops.** `apply_op` drops the BVH only for Add/Remove/Move vertex,
  Add/Remove edge and Add/Remove face. `ChangeEdge` (curve, soft), `PaintFace`, `PaintInstance`,
  instance and guide ops keep it (the index holds positions only; instances and guides are not
  in it).
- **Stencil post-processing samples each new face once.** `face_within` is replaced by
  `FaceSample` (outer corners + centre of its first triangle, computed once per new face before
  any reorientation) and `RingTest` (ring plane, outline and 2D box, computed once per placed
  ring): a new face lies wholly inside or outside every ring tested (the rings were all drawn),
  so the cached point decides. The extra-face filter tests `own` and `split_off` before the
  costlier on-stencil test (pure predicates; same result).
- **Curves upkeep and tagging use the lookups.** `tag_along` walks out from the vertices at the
  segment's ends over edges whose both ends lie on it (drawing the segment joined every vertex on
  it) instead of scanning all edges; `upkeep` takes the curves at moved vertices from
  `edges_at`, soft edges on lost sides from `edge_between`, and counts a soft edge's faces with
  `side_uses` (faces at one end) instead of `face_counts` over every face.
- **Timings (release, this machine; `cargo test --release -p kernel --test perf -- --ignored
  --nocapture`).** Copy 30 circles of 24 sides 3 times: 25.2 s -> 0.74-0.80 s (session-level
  `copy` command: 0.73 s). Undo/redo of that copy: ~1 ms. Move all 2,880 vertices: 278 ms ->
  3 ms. Erase all 2,880 edges: 5.9 ms -> 1.8 ms. Explode a 1,800-face imported group: 1.32 s ->
  0.78 s. Edits inside a 20,000-face imported group (move a vertex, erase an edge, push/pull a
  triangle, draw a line): 0.1-120 ms before and after (they were not the bottleneck at kernel
  level). Drawing 30 circles one by one: ~0.5 s before and after (each draw rebuilds the ground
  plane; see deferred). Timing tests are `#[ignore]` with loose bounds (copy and explode < 3 s,
  each group edit < 1 s).
- **Float round trip.** The workspace `serde_json` dependency enables `float_roundtrip` (no new
  crate; Cargo.lock unchanged). serde_json's default parser misreads about 10% of random doubles
  by one ULP (e.g. 180.17933438838418 -> ...415); with the feature, saved coordinates and camera
  positions reopen bit for bit. It also makes JSON-RPC parsing exact (no behaviour change
  expected). Writing already used shortest round-trip output (ryu).
- **Id limit is consistent.** Ids in a file (entities, curves, definitions, materials) must be
  below `MAX_ID` = 2^53 ("... has an id too large (ids must be below 9007199254740992)") and
  `next_id` at most 2^53, so any scene that loads has `next_id <= 2^53` and its own save loads
  again. Saving a model that has given out ids past 2^53 (only reachable from a file at the
  limit) fails with a `file` error "the model has used ids past 9007199254740992, more than a
  file can hold" and leaves the old file.
- **One number, one thing.** `Scene::validate` claims every raw id once across the whole scene:
  definitions ("d"), materials ("m"), then per mesh its entities ("v", "e", "f", "i", "g") and
  its curves ("c", once per mesh). Same prefix twice: "<id> is used in two meshes"; different
  prefixes: "<a> and <b> share an id" (e.g. "v5 and g5 share an id"). Files written by the app
  never violate it (all ids come from one counter: `alloc`, `new_curve`, `add_definition`,
  `alloc_material`); the whole suite (which saves and reopens groups, components, curves,
  guides and materials) passes with the stricter check. The per-mesh "two entities of different
  kinds share an id" check in `data.rs` stays.
- **Export counts and limits.** `Scene::triangles_and_skipped()` returns the triangles and the
  number of faces that gave none (triangulation failed or empty; counted once per placement);
  `triangles()` keeps its signature. `export` returns `Outcome.export = {"triangles": n,
  "skipped_faces": k}` (new `session::ExportReport`, serialized only for export) instead of
  refusing: one bad face should not block an export. The window status says "Exported <path>
  without k face(s) that could not be triangulated" when k > 0. `export::encode` returns
  `Result`: a binary STL with more than 2^32 - 1 triangles and a `.glb` whose total length does
  not fit 32 bits (about 59.6 million triangles at 72 bytes each) are refused with
  `invalid_input` before anything is written; OBJ and `.gltf` have no such limit. The checks are
  the pure helpers `stl_count` and `glb_lengths`, unit-tested with large numbers (building 60M
  triangles in a test is not feasible). A valid-per-`validate` face that triangulates to nothing:
  a square whose single hole is its own outer loop (used as the test fixture).
- **Test scratch paths.** Every test that writes under `CARGO_TARGET_TMPDIR` now puts the process
  id in its directory or file name (session export/files/guides/import/curves/rotate, api
  import and hub-open, app headless-open), as session camera already did; session materials
  already had it in the file name. The export test that builds a `..` path uses the scratch
  directory's own name. Golden-image failure outputs (`target/tmp/golden/`) are left shared:
  written only on failure.
- **Cheap correctness fixes (t4).** `add_curve` with an open straight polyline returns before
  `new_curve`, so it spends no id (it got no curve anyway). `Scene::copy_instances_placed` on a
  missing mesh returns `DefinitionNotFound`; `erase_instances` on a missing mesh returns an empty
  change (both panicked). An OBJ export whose `.mtl` path differs from the export path only in
  ASCII case is refused like the identical path ("... which is not free").
- **Not changed:** `MAX_COPIES` stays 100 and the context-import cap stays 2,000 faces (raising
  them is a behaviour change for M8d); no new crates.

//! Timings for big edits. Ignored by default (they assert only loose bounds); run them in
//! release to see the numbers:
//! `cargo test --release -p kernel --test perf -- --ignored --nocapture`.

use std::collections::BTreeSet;
use std::f64::consts::TAU;
use std::time::{Duration, Instant};

use glam::DVec3;
use kernel::{DefinitionKind, EdgeId, FaceId, MeshId, MeshPolygon, Model, Scene, VertexId};

fn timed<T>(what: &str, f: impl FnOnce() -> T) -> (T, Duration) {
    let t = Instant::now();
    let out = f();
    let took = t.elapsed();
    eprintln!("{what}: {took:?}");
    (out, took)
}

/// `count` circles with `sides` sides on the ground, six to a row 1 m apart, radius 0.4 m,
/// each a curve with its face.
fn circles(count: usize, sides: usize) -> Model {
    let mut m = Model::new();
    for k in 0..count {
        let c = DVec3::new((k % 6) as f64, (k / 6) as f64, 0.0);
        let pts: Vec<DVec3> = (0..sides)
            .map(|i| {
                let a = TAU * i as f64 / sides as f64;
                c + DVec3::new(a.cos(), a.sin(), 0.0) * 0.4
            })
            .collect();
        m.add_curve(&pts, true).unwrap();
    }
    m
}

/// A `n` x `n` terrain of bent quads (two triangles each, apart from a few flat ones).
fn terrain(n: usize) -> (Vec<DVec3>, Vec<MeshPolygon>) {
    let points: Vec<DVec3> = (0..=n)
        .flat_map(|y| {
            (0..=n).map(move |x| {
                let (x, y) = (x as f64, y as f64);
                DVec3::new(x, y, (x * 0.37).sin() * (y * 0.23).cos() * 2.0)
            })
        })
        .collect();
    let at = |x: usize, y: usize| y * (n + 1) + x;
    let polygons: Vec<MeshPolygon> = (0..n)
        .flat_map(|y| (0..n).map(move |x| (x, y)))
        .map(|(x, y)| MeshPolygon {
            corners: vec![at(x, y), at(x + 1, y), at(x + 1, y + 1), at(x, y + 1)],
            material: None,
        })
        .collect();
    (points, polygons)
}

fn everything(m: &Model) -> (Vec<EdgeId>, Vec<FaceId>) {
    (
        m.edges().map(|(id, _)| id).collect(),
        m.faces().map(|(id, _)| id).collect(),
    )
}

#[test]
#[ignore]
fn time_thirty_circles_copied_three_times() {
    let (mut m, _) = timed("draw 30 circles of 24 sides", || circles(30, 24));
    let (edges, faces) = everything(&m);
    let before = m.clone();
    let (copy, took) = timed("copy them 3 times", || {
        m.copy(&edges, &faces, DVec3::new(7.0, 0.0, 0.0), 3)
            .unwrap()
    });
    assert_eq!(m.faces().count(), 120);
    m.validate().unwrap();
    let after = m.clone();
    timed("undo the copy", || m.apply(&copy.inverse()));
    assert_eq!(m, before);
    timed("redo the copy", || m.apply(&copy));
    assert_eq!(m, after);
    let all: BTreeSet<VertexId> = m.vertices().map(|(id, _)| id).collect();
    timed("move all 2,880 vertices", || {
        m.move_vertices(&all, DVec3::new(0.0, 0.0, 1.0)).unwrap()
    });
    let (edges, _) = everything(&m);
    timed("erase all 2,880 edges", || m.erase(&edges, &[]));
    assert_eq!(m.vertices().count(), 0);
    assert!(took < Duration::from_secs(3), "copy took {took:?}");
}

        s.edit(mesh, |m| Ok(m.erase(&[e], &[]))).unwrap();

    time("push/pull one triangle 1 m", &mut |s| {
        s.edit(mesh, |m| m.push_pull(f, 1.0)).unwrap();
    });
    time("draw a line above the terrain", &mut |s| {
        s.edit(mesh, |m| {
            m.add_edge(DVec3::new(10.5, 10.5, 9.0), DVec3::new(20.5, 30.5, 9.0))
        })
        .unwrap();
    });
    scene.validate().unwrap();
    assert!(worst < Duration::from_secs(1), "an edit took {worst:?}");
}
