# M19e Cut List Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A shop-ready list of the model's parts: name, material, length, width, thickness and quantity, in the window, over the API, as CSV, on a page of the PDF, and with the same sizes on the phone viewer's parts list.

**Architecture:** A kernel `cutlist.rs` walks the instances of a mesh down to parts (a part is a definition's own faces placed by an instance), takes each part's size from its own bounding box scaled by the composed placement, finds its material and whether it is a solid, and groups identical parts. A session `cut_list` query turns that into rows; a session `cutlist.rs` writes CSV and page text in the model's display units. The app adds a Tools > Cut List window; `render::print` and `export_pdf` add the cut-list page; the viewer's parts list shows the part's own box.

**Tech Stack:** Rust 2024. No new dependencies.

**Spec:** `docs/superpowers/roadmap.md` row M19e. Uses M18d (`solid`, material by face), M13d2 (print), M14f (display units), M16d (parts list).

## Spec notes (rulings)

1. **What a part is.** A definition's own faces, placed by an instance. A leaf group or component (faces, no nested instances) is one part. A group that holds instances (a cabinet) lists its sub-parts instead of itself, to any depth (64 at most); if it also has faces of its own, those are one more part under its name. Empty definitions (no faces) are not parts. Hidden instances (hidden themselves or by tag) are not listed.
2. **Size.** The part's own box: the extent of the definition's vertices along its own axes, times the length of each axis of the composed placement (the product of the instance matrices from the listed root instance down), so a board turned 30 degrees reads its true size and a scaled instance reads its scaled size. The three sizes are written longest to shortest as length, width, thickness. A shear in the placement is not followed (the axis lengths are used).
3. **Material.** The material most (over half) of the part's faces show on the outside (front, or back when the solid faces inward, as in mass), else the part's instance's, else the nearest enclosing instance's, else none (shown as blank, sorted last).
4. **Solid.** A part is a solid when its mesh is closed and encloses a volume (`open_reason`). Parts that are not are listed with `solid: false` and a `note` giving the reason, never dropped.
5. **Grouping.** `group_by: "definition"` (default) merges parts with the same definition, material, solidity and size (to 0.1 micrometer), summing quantity; `"none"` gives one row per part. The row's `ids` are the listed root instances (the ones that can be selected), sorted, without repeats; a cabinet of four identical legs is one row of quantity 4 with the cabinet's id. `ids` in the query limit the root instances considered (instances of the open context, like `mass_properties`).
6. **Order.** By material name (case blind, no material last), then length, width, thickness descending, then name, then first id.
7. **Units.** The window and the page show sizes with `format_length` in the model's units. CSV cells are plain numbers in the display unit (feet and inches in decimal inches), the unit named in the header (`Length (mm)`). Text fields follow RFC 4180 (quoted when holding a comma, quote, CR or LF, quotes doubled, CRLF line ends); a text field that starts with `=`, `+`, `-` or `@` gets a leading apostrophe so a spreadsheet does not run it.
8. **CSV export.** `export` with format `csv` (extension `.csv`) writes the cut list of the whole root, grouped by definition.
9. **PDF.** `export_pdf { cut_list: true }` and a "Cut list page" option on the Print sheet add pages after the view's sheets: a table (name, material, L, W, T, qty) in the display units, as many pages as the rows need; the reply's `sheets` counts them.
10. **Phone viewer.** The parts list shows each part's own box, longest first ("L x W x T"), instead of the world box.
