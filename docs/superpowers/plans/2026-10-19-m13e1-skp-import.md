# M13e1 SketchUp Import (2021+ files) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import and open SketchUp `.skp` files saved by SketchUp 2021 and newer: geometry with holes, soft edges, groups and components with nested transforms, materials and textures, guides, with a report of what was not carried.

**Architecture:** openskp-rs's `skpcore` is vendored as a new workspace crate `skp` (MIT, kept close to upstream). The `session` crate reads the file through it into a neutral import tree (definitions, faces as index loops, instances with affine transforms) that a new kernel entry point, `Scene::import_tree`, builds into our scene: one definition per SketchUp definition, shared by its instances. `Command::Import` gains the `skp` format; `Command::Open` opens a `.skp` as a new untitled model.

**Tech Stack:** Rust 2024 (the vendored crate stays on edition 2021), miniz_oxide =0.8.9 (already in Cargo.lock through png), glam, image =0.25.10. No other new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-10-sketchup-alt-design.md`, the M13e1 bullet under "Modeling parity milestones"; background in `docs/superpowers/research/2026-10-19-skp-readers.md`.

## Global Constraints

- No new crates beyond the vendored `skp` crate; `miniz_oxide` is pinned `=0.8.9` in `[workspace.dependencies]`. `memmap2` is not added.
- Nothing from Hew (hew3d, AGPL) or hew3d/openskp (GPL) is read or used. The SketchUp SDK is not used.
- The vendored crate keeps upstream's MIT `LICENSE` (copyright Hakko Kim) and records the upstream commit; edits to it are listed in its `VENDORED.md`.
- Test fixtures in the repo are only the CC BY 4.0 files `cupboard.skp` and `desk.skp` (Corynth), with `ATTRIBUTION.md` next to them. Trimble's sample files are never committed; corpus-wide tests read `SKP_CORPUS` (a folder path) and are `#[ignore]`d.
- A malformed file must give an error or a reported skip, never a panic, hang or unbounded allocation.
- Existing behaviour is unchanged: OBJ/STL import, `.skr` open/save, golden images; every existing test keeps passing.
- Gate per task: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` (about 11 minutes). Use `export PATH="$HOME/.cargo/bin:$PATH"`. Integration tests are modules of `crates/<crate>/tests/integration/main.rs`.
- `docs/agent-api.md` is updated in the task that changes the API. No emoji. Commit messages short, no attribution lines. Never `git add -A`.

## Spec notes (rulings)

1. **Vendoring:** copy upstream `core/skpcore/src` (all modules, including `legacy.rs` for M13e2) into `crates/skp/src`, package name `skp`, `edition = "2021"`, `publish = false`, MIT. Remove `FileSource` and the `memmap2` dependency (the only `unsafe`); keep `MemorySource`. Keep upstream tests out (they need a private corpus). Add `#![allow(clippy::all)]` at the crate root with a comment that the code is upstream's; rustc warnings are fixed, not allowed. Upstream commit: `sources/openskp-rs.commit` in `../sketchup-skp-corpus`.
2. **Fixes in the fork** (each listed in `VENDORED.md`): `InflateRead::pump` keeps calling `inflate` with empty input after the input is used up until `StreamEnd` or no progress; `ByteSource::read_vec`, `ZipDirectory` reads and `read_entry` refuse a length larger than the source (`Error::OutOfRange`) before allocating; `Vec::with_capacity` of a count read from the file is capped by what the source could hold; unchecked `u64` additions on file offsets use `checked_add` (`Error::Malformed` on overflow).
3. **Import tree** (kernel, new module `crates/kernel/src/import_tree.rs`): `pub struct ImportTree { pub definitions: Vec<ImportDefinition>, pub root: ImportGeometry }`; `pub struct ImportDefinition { pub name: String, pub kind: DefinitionKind, pub geometry: ImportGeometry }`; `pub struct ImportGeometry { pub points: Vec<DVec3>, pub faces: Vec<ImportFace>, pub edges: Vec<ImportEdge>, pub guides: Vec<Guide>, pub instances: Vec<ImportInstance> }`; `pub struct ImportFace { pub loops: Vec<Vec<usize>>, pub front: Option<MaterialId>, pub back: Option<MaterialId> }` (loop 0 outer, others holes, any winding); `pub struct ImportEdge { pub a: usize, pub b: usize, pub soft: bool }` (every edge the file has, so loose edges are kept and face sides can be softened); `pub struct ImportInstance { pub definition: usize, pub transform: DAffine3, pub material: Option<MaterialId> }`.
4. **Building:** `Scene::import_tree(&mut self, parent: MeshId, tree: &ImportTree, kind: DefinitionKind, name: &str) -> Result<(InstanceId, TreeReport, SceneChange), KernelError>` builds every definition into a new definition of ours (same order), then the root geometry into one new definition named `name` of `kind` placed once with the identity in `parent`. Per geometry: points welded as `build_mesh` does; each face's loops oriented (outer counter-clockwise around the face normal from the outer loop's vector area, holes clockwise); a face whose loops are flat (`FLAT_TOL`) and valid (`rings_are_valid`) is one face with holes, otherwise its outer loop goes through the existing `pieces` cutting (holes dropped) and it counts in `TreeReport::split`; a face with no valid outer loop counts in `skipped`. Edges are inserted for every `ImportEdge` (loose ones too, duplicates once); `soft` is applied with `soften_edges` after faces exist (edges not between two faces stay hard, counted in `TreeReport::hard`). Guides are added with `add_guide` (invalid ones counted in `skipped_guides`). Instances: `Instance { definition: ours[i], transform, material }` inserted into the geometry's mesh. `TreeReport { definitions, instances, faces, vertices, skipped, split, hard, skipped_guides }`.
5. **Tree checks** (before building anything; `KernelError::InvalidImport(String)`, a new variant with a message): an instance's `definition` out of range; a definition reachable from itself (cycle); nesting deeper than `MAX_IMPORT_DEPTH = 32`; more than `MAX_IMPORT_DEFINITIONS = 10_000` definitions or `MAX_IMPORT_INSTANCES = 100_000` instances; a transform not finite or with `|det| < MIN_DETERMINANT`; any point not finite; total faces over all definitions above `MAX_IMPORT_FACES` (`TooManyFaces`). Definitions no instance reaches from the root are not built (counted in `TreeReport::unused`). Nothing changes on an error.
6. **Reading .skp** (session, new module `crates/session/src/skp.rs`): read the file within `MAX_IMPORT_BYTES` (as OBJ/STL); `Container::open`; a legacy container is refused with `invalid_input` "SketchUp 2020 and older files cannot be imported yet; open the file in SketchUp 2021 or newer and save it again"; `scene::read_model` with default `ReadOptions`; `Model::index` for materials. Map per definition (by `u64` pid; never the `as u32` tables): vertices scaled by `0.0254 * scale`; faces via `loop_ring` per loop (a face whose loop 0 fails is skipped and counted; failed holes are dropped and counted); edges with `soft = flags & (SOFT|SMOOTH|HIDDEN) != 0`; `RawInstance.matrix4()` to `DAffine3` (its 3x3 as is, translation times `0.0254 * scale`); `is_image` instances skipped and counted; an instance whose `def_pid` is unknown skipped and counted. `Definition` kind: Group when every placement of it has `is_group`, else Component; name from the definition (empty: "Group" / "Component").
7. **Materials:** one of ours per `MaterialDef` actually used by a face or instance (names made unique with " 2", " 3"... against the model's existing names, as `add_material` naming does today; `Layer_*` tag colours are already filtered by the reader): `rgba` to colour, `opacity`; a texture is read with `Container::read`, checked with `texture::dimensions` and decoded with `texture::decode` under the existing limits (`MAX_TEXTURE_BYTES`, pixel limits, `MAX_TEXTURES`); its size is `tile_mm_drawable()` in meters times `scale`, each clamped to `[MIN_TEXTURE_SIZE, MAX_TEXTURE_SIZE]`. A texture that fails keeps the material as its colour and counts as a warning. More than `MAX_IMPORT_MATERIALS` used materials: the rest import as no material, with a warning. On any later error the materials added are removed, as the OBJ path does.
8. **Report:** `ImportReport` gains `definitions: usize`, `instances: usize`, `guides: usize`, `textures: usize` (serde default, skipped when 0) and `warnings: Vec<String>` (skipped when empty), plain sentences such as "4 tags were not imported (tags are not supported yet)", "2 scenes were not imported", "3 hidden faces were imported visible", "1 image was skipped", "5 face holes could not be read and were dropped", "2 faces were cut into triangles". `polygons` counts faces in the file, `faces` faces made, `skipped` faces not made. OBJ/STL reports are unchanged (the new fields stay empty).
9. **Format and placement:** `ImportFormat::Skp` (`"skp"`), from the `.skp` extension; when `format` is absent and the extension is not known, a file whose header is SketchUp's (UTF-16 "SketchUp Model") is `Skp`. `up` is ignored for `.skp` (no error), `merge_coplanar` is ignored (faces are kept as SketchUp has them). `as`: `group`/`component` wrap as today (the wrapper definition is named after the file stem); `context` explodes the wrapper as today, under the same `MAX_CONTEXT_IMPORT_FACES` limit for the root geometry.
10. **Open:** `Command::Open` with a `.skp` path (by extension or header) builds a new document: `New` semantics (`unsaved_changes` unless `discard`), then the tree's root geometry goes straight into the root mesh (no wrapper; `Scene::import_tree_into_root` — the same builder with the root geometry inserted into `parent` itself, allowed only when `parent` is empty, else `InvalidImport`), the document has no path, is not modified, the camera zooms to extents, and the outcome carries the import report. Saving asks for a `.skr` path as for a new model. The CLI FILE argument and File > Open (dialog filter adds "SketchUp model" `skp`) use the same command.
11. **Window:** the File > Import dialog filter becomes "OBJ, STL or SketchUp" `["obj","stl","skp"]` plus a "SketchUp" filter; the import options sheet hides Units and Up axis for a `.skp` (and "Merge coplanar faces"); the status message after an import lists the counts and, when there are warnings, "with N warnings (see the import report)"; for File > Open of a `.skp` the window title is "<name>.skp (imported)" until saved.

## Review Focus

1. A component placed several times (cupboard handles, desk legs) must become one shared component definition with several instances, not copies; editing one edits all. Test in Task 3.
2. Mirrored and scaled SketchUp instances (a mirrored handle) import with faces pointing out. Test in Task 2 (synthetic) and Task 3 (fixture bounds and face count).
3. A truncated or bit-flipped `.skp` must return an error or a report, never panic, and never allocate more than the file justifies. Test in Task 1 (fork) and Task 3 (import over mutated fixtures).
4. Opening a `.skp` when the current model has unsaved changes is refused without `discard`, and after opening, Save asks for a new `.skr` path (it must never write over the `.skp`). Test in Task 4.
5. Materials named like existing ones do not clobber them; textures over the limits leave a coloured material and a warning. Test in Task 3.
