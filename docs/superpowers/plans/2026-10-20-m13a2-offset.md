# M13a2 Offset Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SketchUp's Offset: draw a copy of a face's edges (or of a chain of connected edges) a set distance inside or outside it, in its plane, as a command and a tool that agents can drive.

**Architecture:** A pure geometry function in the kernel offsets closed loops and open chains in a plane with mitred corners (bevelled past a miter limit) and refuses results that cross themselves or (for an inward face offset) leave the face. The `offset` command computes the new points and draws them with the existing sticky geometry (`Model::draw_segments` / `add_curve`), which splits the face along the new loop exactly as drawing it by hand would. The Offset tool follows the Push/Pull tool's pattern (pick, drag a distance, type a length, retype, double-click to repeat).

**Tech Stack:** Rust 2024, glam. No new dependencies.

**Spec:** `docs/superpowers/roadmap.md` row M13a2 (the M13a bullet in `docs/superpowers/specs/2026-10-10-tenon-design.md` lists Offset: "face or connected edges, typed distance").

## Spec notes (rulings)

1. **Command:** `offset {ids, distance, toward?}`. `ids` is one face, or edges forming one connected chain in one plane (open, or closed into a loop; branching is `invalid_input`). For a face, `distance > 0` offsets inward and `< 0` outward; every loop of the face is offset (the outer loop inward, holes outward, for a positive distance), and `toward` is not allowed. For edges, `toward` (a point in the chain's plane, not on the chain) picks the side and `distance` must be positive. `distance` is finite and its size at least `10 * LENGTH_TOL`, else `invalid_input`. One undo step, label `offset`.
2. **Geometry** (`crates/kernel/src/offset.rs`, pure): `pub fn offset_loop(points: &[DVec3], normal: DVec3, distance: f64) -> Result<Vec<DVec3>, OffsetError>` (a counter-clockwise loop around `normal`; positive moves left of each side, i.e. inward) and `pub fn offset_chain(points: &[DVec3], normal: DVec3, distance: f64) -> Result<Vec<DVec3>, OffsetError>` (positive moves left of the walking direction; end points move perpendicular to their own side). Corners are mitred; where the miter would be longer than `4 * |distance|` the corner is bevelled (two points). Points closer than `LENGTH_TOL` to the previous one are merged. `OffsetError::{SelfCrossing, Collapsed}`: the result crosses itself, or a side reverses direction or shrinks below `LENGTH_TOL` (the shape is too small for the distance). For a face offset inward, every new loop must lie strictly inside the face (inside the outer loop, outside every hole), else `Collapsed`. The caller maps errors to `invalid_input` "the offset distance is too large for this shape".
3. **Drawing:** the new points are drawn in the open context with the sticky-geometry path a hand drawing uses (`draw_segments`, or `add_curve` when tagging), as one change. When every source edge is on one curve (a circle, arc or polygon from M6/M13a1), the new edges are one curve of the same kind (`polygon` flag kept). The outcome lists the created edges and faces (the face split by an inward offset shows as modified/created as the kernel reports).
4. **Tool:** Offset tool, key `o`, label "Offset", icon a Phosphor glyph that reads as offset (pick one present in egui-phosphor 0.14.0, e.g. `ph::SQUARES_FOUR` or `ph::FRAME_CORNERS`, and say which), modify group after Scale. With nothing selected, hovering a face highlights it; with edges selected that form a chain, those are used. Press on the face (or a selected edge) and move: the distance is the cursor's distance, in the plane, from the nearest source side, signed inward/outward for faces; for chains the side is the cursor's side. Release after a drag or a second click finishes. Typed length finishes; typed after an offset redoes it (`[Undo, Offset]`). Double-click on a face offsets it by the last distance. Preview: the offset loops as lines; an invalid distance shows the error message instead.
5. **tool_input:** the tool works through `tool_input` like the others (click a face point, move, type).

## Review Focus

1. A concave face (an L-shape or a star) offset inward by a valid distance stays one simple loop; by too large a distance it is refused, never drawn crossing itself. Test in Task 1.
2. A face with a hole offset inward shrinks the outer loop and grows the hole; the resulting ring between them is a face. Test in Task 1.
3. Offsetting a circle (a tagged curve) gives a circle curve with the same segment count. Test in Task 1.
4. An open chain of edges offset to the side of `toward` lands on that side even when the chain doubles back. Test in Task 1.
5. The tool's typed distance after an offset redoes it, and double-click repeats the last distance on another face. Test in Task 2.
