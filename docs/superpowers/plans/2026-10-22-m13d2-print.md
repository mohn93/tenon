# M13d2 Print, PDF and SVG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Print and PDF export of the current view fitted to one sheet, or of the whole model at an exact scale (1:N, parallel projection) tiled across sheets with trim marks and a scale bar; and an SVG line drawing of the current view (visible edges only, section cuts and fills, dimension and note labels).

**Architecture:** Three layers. (1) `session::drawing`: a CPU line drawing of a view — every shown, non-soft edge of every placement (section cuts applied as in M13d1), split into short screen-space pieces whose midpoints are tested for visibility by ray casts against the placed meshes' BVHs (`kernel::Index`), with section fill polygons as extra occluders; plus cut edges, fills and annotation shapes and label text; written as SVG by `session::svg` through the existing `Command::Export` (`.svg`). (2) `session::pdf`: a small hand-written PDF writer (pages, RGB image XObjects compressed with `miniz_oxide`, vector paths, Helvetica text) and `session::print`: paper sizes, sheet layout, tiling at 1:N and the camera for each tile (a parallel camera panned per tile). (3) The app/host renders the tiles with the GPU (`Snapshotter`, scene set once, one capture per tile), draws labels, trim marks and the scale bar as vectors, and writes the PDF: editor command `export_pdf` (window and agents), File > Export PDF... and File > Print... (writes a temporary PDF and opens it in the system's default viewer, from which the user prints; no OS print API).

**Tech Stack:** Rust 2024, egui 0.36.2, wgpu 30. `miniz_oxide =0.8.9` (already a workspace dependency used by `skp`) may be added to `session`. No other dependencies; `Cargo.lock` gains no package.

**Spec:** `docs/superpowers/roadmap.md` row M13d2.

## Spec notes (rulings)

1. **Line drawing** (`session::drawing::line_drawing(doc, camera, size_px) -> Drawing`): edges that are shown (tags, hidden instances, soft edges excluded, section cuts and display applied exactly as the renderer and picking do), projected with the camera; each edge is cut into pieces of at most 2 px on screen (at most 256 pieces per edge), a piece is visible when the ray from the camera's sight origin to the piece's midpoint hits nothing (faces of any shown placement, and section fill polygons) closer than the point minus 1e-6 x distance; consecutive visible pieces are merged into one polyline. Cut edges (section outlines) and fills are included as such (fills drawn as grey polygons under the lines). Dimensions and notes: their lines and their label text at the projected label position (labels measured on placed shapes as in M13c; screen notes at their view fraction). Guides and section plane outlines are not drawn. A drawing with more than 2,000,000 tested pieces is refused ("the model is too large for a line drawing at this size").
2. **SVG** (`.svg` export, `Command::Export`): `width`/`height` = the view size in px unless the camera is parallel and `scale: Some(N)` is given, in which case the SVG is in millimetres at 1:N (viewBox in mm). Lines: black, 1 px (0.25 mm at scale), cut edges 3x, fills `#3a3a3a` at 100%, text Helvetica/sans-serif 11 px (3 mm). Deterministic output (fixed float formatting, 3 decimals).
3. **Print layout** (`session::print`): paper A4 (210x297 mm), A3 (297x420), Letter (215.9x279.4), Legal (215.9x355.6), Tabloid (279.4x431.8); portrait or landscape; margins 10 mm. **Fit** mode: the current view (its aspect kept) fitted into the printable area of one sheet. **Exact 1:N** mode (parallel camera only; refused in perspective with "Switch to parallel projection to print at scale"): the model's shown bounds projected along the current view direction, laid out at 1:N, tiled across ceil(w/W) x ceil(h/H) sheets (refused above 100 sheets with the count), each sheet's printable area showing its tile; trim marks (5 mm lines at each printable-area corner, outside it) when more than one sheet; a scale bar (a "nice" length 1/2/5 x 10^k metres between 20 and 60 mm on paper, labelled "0" and the length in display units, with "1:N") in the bottom margin of every sheet; a footer text "Sheet r,c of R x C" when tiled. Resolution 150 dpi default, 72..=300 allowed; tile pixel size = printable area mm x dpi / 25.4, rendered in chunks no larger than 4096 px per side.
4. **PDF** (`session::pdf`): PDF 1.4, one page per sheet, MediaBox in points (mm x 72 / 25.4), an RGB image per tile chunk (`/FlateDecode` via miniz_oxide), vector lines for trim marks and scale bar, dimension/note label text as Helvetica (base-14, WinAnsi; characters outside it replaced by "?") placed over the image; deterministic bytes (no dates, fixed ids).
5. **Editor command** `export_pdf { path, paper?: "a4"|"a3"|"letter"|"legal"|"tabloid" (default a4), landscape?: bool (default true), scale?: number (1:N; absent = fit), dpi?: number (default 150), overwrite?: bool }` — renders with the GPU (window or headless with an adapter; without one: an error "printing needs a GPU adapter"), result reports sheets, pages and warnings. Path rules as exports (api roots, overwrite, not the open model).
6. **Window:** File > Export PDF... and File > Print... open a Print sheet (paper, orientation, Fit / 1:N with N field, resolution) — Export PDF then asks for the file with a save dialog; Print writes the PDF to the system temp folder (`tenon-print-<pid>-<n>.pdf`, private file) and opens it with the default viewer (`open` on macOS, `xdg-open` on Linux, `cmd /C start "" <path>` on Windows), reporting failure in the status line. The sheet remembers its last values in prefs. File > Export... gains SVG.

## Review Focus

1. A box seen from an iso view: the SVG has its visible edges only (no back edges), edges ending at silhouettes are split correctly, and lines on faces (drawn edges on a face) stay visible.
2. A section-cut model: the SVG shows cut edges and fill and does not show the interior back faces' edges behind the fill.
3. Exact 1:100 on A4 of a 50 m long building: the tiles abut exactly (no gap or overlap of model content between sheets: tile cameras are panned by exactly the tile's world size), trim marks and scale bar measure correctly on paper.
4. PDF output opens in standard viewers (valid xref offsets, stream lengths, object numbering) and is byte-identical between two runs.
5. Perspective camera with a scale is refused clearly; more than 100 sheets refused; a GPU-less headless `export_pdf` errors cleanly.
