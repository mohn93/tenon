# M13e3 SketchUp Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export the model as a SketchUp `.skp` file (SketchUp 2017 format, which SketchUp 2017 and every later version opens), keeping groups and components, faces with holes, soft edges, materials and textures, and guides.

**Architecture:** A new crate `skpwrite` ports openskp's Python writer (MIT; `create.py`, the only up-to-date port) to Rust: it splices a scene into openskp's 5,796-byte blank 2017 document (embedded with `include_bytes!`), writing the MFC archive records (materials, layers, component definitions, groups and instances, faces with loops and edge uses, edges, guides) and patching the counts and slot references. It takes a neutral document type and has no kernel dependency. The `session` crate maps our scene to that type and adds `ExportFormat::Skp`. Our own reader (`skp::legacy`) is the test oracle; SketchUp 2024 on the development machine is the final check.

**Tech Stack:** Rust 2024. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-10-tenon-design.md`, the M13e3 bullet; research in `docs/superpowers/research/2026-10-19-skp-readers.md`.

## Spec notes (rulings)

1. **Writer input** (`crates/skpwrite/src/doc.rs`), all lengths in inches: `pub struct Doc { pub materials: Vec<Material>, pub definitions: Vec<Definition>, pub root: Geometry }`; `pub struct Material { pub name: String, pub rgba: [u8; 4], pub opacity: f64, pub texture: Option<Texture> }`; `pub struct Texture { pub bytes: Vec<u8> /* PNG or JPEG as stored */, pub width: f64, pub height: f64 }`; `pub struct Definition { pub name: String, pub is_group: bool, pub geometry: Geometry }`; `pub struct Geometry { pub vertices: Vec<[f64; 3]>, pub edges: Vec<Edge>, pub faces: Vec<Face>, pub instances: Vec<Instance>, pub guides: Vec<Guide> }`; `pub struct Edge { pub a: u32, pub b: u32, pub soft: bool, pub smooth: bool, pub hidden: bool }`; `pub struct Face { pub loops: Vec<Vec<u32>> /* outer first, CCW around the face's normal; holes CW */, pub front: Option<usize>, pub back: Option<usize>, pub front_uv: Option<[([f64; 3], [f64; 2]); 3]>, pub back_uv: Option<[([f64; 3], [f64; 2]); 3]> }`; `pub struct Instance { pub definition: usize, pub rotation: [[f64; 3]; 3] /* row-major as SketchUp stores it */, pub translation: [f64; 3], pub material: Option<usize> }`; `pub enum Guide { Line { point: [f64; 3], direction: [f64; 3] }, Point { position: [f64; 3] } }`. Edges used by faces must be listed in `edges` (the writer looks them up by vertex pair); edges no face uses are written as loose edges.
2. **Writer API:** `pub fn write(doc: &Doc) -> Result<Vec<u8>, WriteError>`; `WriteError` variants for: a face loop with fewer than 3 vertices or an index out of range, a face edge missing from `edges`, a definition placing itself (directly or through others), an instance of a definition out of range, a material or texture index out of range, a texture that is neither PNG nor JPEG, a string longer than 254 UTF-16 units (callers truncate names first), a non-finite number, an empty document (no root entity). Definitions are written in an order where every definition comes after those it places (computed, not required of the caller); definitions placed by nothing are still written. Empty definitions are given no entities and are not written (the writer drops them and anything placing them reports `WriteError` — callers skip empty definitions first).
3. **Records** follow openskp's Python writer: the scaffold splice and patch points (header pid counter at 1987 as one running u32 counter for the whole file, camera patches, layer count at 3405, active-layer anchor shift, definition count at 3507, root count at 3511, the six tail slot references), slot numbering with inline class declarations and the `7f ff` + u32 escape past 0x7FFF, the drawbase (offsets 3-4 are 1, 1), `CFace` with Newell plane and back material, `CLoop`/`CEdgeUse` with edge sense, `CMaterial` (solid and textured with `CDib`; JPEG trailer 90; average colour alpha 254), `CComponentDefinition` with the embedded Layer0, GUID, name and thumbnail template, `CComponentInstance`/`CGroup` with the 3x3, translation and the 1.0 divisor, `CConstructionLine` (infinite: ±1e30) and `CConstructionPoint`. Only Layer0 is written (no tags until M13b). Edge flags are written per edge (soft, smooth, hidden), which openskp's API did not allow; loose edges are top-level `CEdge` entities.
4. **Session mapping:** the whole scene is exported (root and every definition reachable from it, in model coordinates of each definition; not the open context only). Meters to inches (`/ 0.0254`). Faces: outer loop and holes as stored (already CCW/CW around the face normal); front and back materials. Edges: every edge of the mesh; `soft` edges written soft and smooth. Instances: our `DAffine3` matrix3 written row-major (`rotation[i][j] = matrix3.col(j)[i]`), translation in inches; `material`; group vs component from the definition kind. Guides: lines and points. Materials: colour, opacity; textures with their stored encoded bytes and size in inches; each textured face gets explicit front UV pins from three non-collinear outer-loop corners using `Face::texture_position` divided by the texture size (and back pins from `back_texture_position`), so placements survive; emission is dropped. Curves (circle, arc, polygon marks) are not written in this milestone: their edges are written plainly (soft flags kept).
5. **Export report:** `ExportReport` gains `definitions`, `instances`, `faces`, `edges`, `guides`, `materials` (serde default, skipped when 0) and `warnings: Vec<String>` (skipped when empty): "N materials glow; SketchUp files cannot store that", "N curves were written as separate edges", "N empty groups or components were left out". Triangle-based fields stay as they are for other formats.
6. **Command and window:** `ExportFormat::Skp` (`"skp"`, from the `.skp` extension). `export` to `.skp` keeps the existing protections: the open model's own file is refused, an existing file that is not a SketchUp file is refused unless `overwrite`, symbolic links refused under `--api-root`. An existing `.skp` (sniffed `Kind::Skp`) may be replaced. File > Export lists "SketchUp 2017 (.skp)". A model with nothing to write gives `invalid_input` "nothing to export".

## Review Focus

1. Round trip: a scene exported and imported again has the same definitions, instances, faces (with holes), edges (soft kept), guides, materials (colour, opacity, texture bytes and size) and bounds within 1e-6 m. Test in Task 2.
2. Sharing: a component placed several times is written once and placed by instances, not duplicated. Test in Task 2.
3. Slot numbering past 0x7FFF and long names: a model with more than 40,000 entities writes and reads back. Test in Task 1.
4. Determinism: exporting the same scene twice gives identical bytes. Test in Task 1.
5. A file SketchUp itself opens: the controller opens the exported cupboard, a textured model and a large model in SketchUp 2024 after Task 2 (Ruby console script: open, count entities, save a 2024 copy), and the counts must match the export report.
