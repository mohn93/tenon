# M15b Windows Build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The window app, headless mode and the MCP server build and run on Windows 10 and 11 (x86_64): the agent API over an owner-only named pipe, app files in the Windows user folders with owner-only access, `--api-root` correct with drive letters and UNC paths, CI that builds and tests on Windows, and an unsigned zip.

**Architecture:** The API's transport gets an endpoint abstraction: Unix keeps its socket; Windows uses a named pipe created with an owner-only security descriptor and remote clients rejected (through `windows-sys` 0.61.2, already in Cargo.lock). The line protocol (`serve_stream`) is unchanged. App folders on Windows are created with a protected owner-only DACL and refuse reparse points. Path checks normalise Windows verbatim prefixes and compare case-insensitively. Unix-only tests are gated and Windows counterparts added. A Windows CI job runs fmt, clippy and tests, and a release job packages `app.exe` into a zip.

**Tech Stack:** Rust 2024; `windows-sys = "=0.61.2"` as a `cfg(windows)` dependency (no new crate in the lock); GitHub Actions `windows-2022`.

**Spec:** `docs/superpowers/roadmap.md` row M15b.

## Global Constraints

- No new crates in Cargo.lock: `windows-sys` is pinned to `=0.61.2` (the version already locked) with only the features needed (`Win32_Foundation`, `Win32_Security`, `Win32_Security_Authorization`, `Win32_Storage_FileSystem`, `Win32_System_Pipes`, `Win32_System_Threading`, `Win32_System_IO`, `Win32_System_Console`, `Win32_UI_Shell` if known folders are used).
- macOS and Linux behaviour is unchanged; every existing test keeps passing there.
- All `unsafe` Windows calls live in one module per crate (`crates/api/src/windows.rs`, `crates/app/src/windows.rs`), each block with a `// SAFETY:` comment; no `unsafe` elsewhere.
- No Windows machine is available: implementers check Windows code with `rustup target add x86_64-pc-windows-msvc` (an official Rust standard library download, sanctioned by this plan) and `cargo check --workspace --all-targets --target x86_64-pc-windows-msvc` plus `cargo clippy` for that target (no linking needed); Windows tests run only in CI, which the controller pushes and reads.
- Gate per task: fmt, clippy `-D warnings` and `cargo test --workspace` on macOS, plus `cargo clippy --workspace --all-targets --target x86_64-pc-windows-msvc -- -D warnings`. `export PATH="$HOME/.cargo/bin:$PATH"`.
- Docs updated in the task that changes behaviour (`docs/windows.md` new; `docs/agent-api.md`, `docs/mcp.md`). No emoji. Short commit messages, no attribution lines. Never `git add -A`.

## Spec notes (rulings)

1. **Endpoint:** `api::transport` gains `pub enum Endpoint { #[cfg(unix)] Socket(PathBuf), #[cfg(windows)] Pipe(String) }` with `pub fn listen(endpoint: &Endpoint, inbox: Inbox) -> io::Result<()>` and `pub fn connect(endpoint: &Endpoint) -> io::Result<(Box<dyn Read + Send>, Box<dyn Write + Send>)>`; `listen_unix` becomes the Unix arm; `SocketBackend` uses `connect`. CLI: `--socket NAME` and `--live NAME` take a path on Unix and a pipe name on Windows (`\\.\pipe\<name>`; a bare name gets the prefix). Default Windows endpoint: `\\.\pipe\sketchup-alt-<pid>`.
2. **Named pipe:** created with `CreateNamedPipeW` (`PIPE_ACCESS_DUPLEX`, `PIPE_TYPE_BYTE | PIPE_READMODE_BYTE | PIPE_WAIT | PIPE_REJECT_REMOTE_CLIENTS`, `FILE_FLAG_FIRST_PIPE_INSTANCE` for the first instance so a second program cannot take the name), unlimited instances, with a security descriptor granting full access to the current user's SID only (from the process token) and nothing to anyone else; an accept loop creates the next instance before serving each connected client on its own threads (reader and writer as `File` handles via `try_clone`). A name already in use: `AddrInUse` like Unix. Clients connect with `CreateFileW` (or `OpenOptions` on the pipe path).
3. **Paths (Windows):** `paths::Os::Windows`: prefs `%APPDATA%\sketchup-alt\prefs.json`, recovery `%LOCALAPPDATA%\sketchup-alt\recovery`; an env value is used only if absolute; missing `APPDATA`/`LOCALAPPDATA` fall back to `%USERPROFILE%\AppData\Roaming` / `\Local`; no usable profile: as today (warning, no prefs, no recovery).
4. **Private folders and files (Windows):** `ensure_private_dir` on Windows creates the folder with a protected DACL (owner full control, inheritance off, inherited by children) and, for an existing folder, refuses a reparse point (symlink or junction, via the file attributes) — it does not rewrite an existing folder's ACL. Partial files written inside such a folder inherit it; `replace_file`'s `Access::Private` on Windows creates the partial file with the same owner-only descriptor.
5. **`--api-root` on Windows:** roots and resolved paths are normalised: verbatim `\\?\C:\` becomes `C:\`, `\\?\UNC\server\share` becomes `\\server\share`; comparisons are case-insensitive on Windows; the last-component logic uses `Path` components, not `/`; drive-relative (`C:foo`) and rooted-without-drive (`\foo`) paths are refused (`invalid_input`); reparse points are treated like symlinks; names with `:` (alternate data streams) and reserved device names (`CON`, `NUL`, `COM1`…, with any extension) are refused. The same normalisation applies to MTL library roots in the OBJ importer.
6. **Console:** one console-subsystem `app.exe` (headless, stdio and MCP need stdin/stdout). In window mode, when the process's console has only this process (`GetConsoleProcessList` returns 1, i.e. it was started from Explorer), it calls `FreeConsole` so no console window stays open. `main` reads arguments with `args_os` and refuses non-Unicode ones with a message instead of panicking.
7. **Tests:** Unix-only tests (permission modes, symlinks, Unix sockets, `/`-rooted absolute paths) are gated `#[cfg(unix)]`; Windows counterparts cover the named pipe round trip (headless app over a pipe, MCP `--live` over a pipe), paths resolution with a fake environment, the DACL on a created private folder (owner SID only, protected) and a junction being refused (junction creation needs no privilege), roots normalisation (verbatim, UNC, case, refused forms). `.gitattributes` marks `*.skp`, `*.png`, `*.jpg`, `*.skr` as binary.
8. **CI and package:** a `windows` job on `windows-2022` (shell bash; no GPU, so wgpu uses WARP or skips; goldens skip on software adapters already) running fmt, clippy and tests, with the same cache and timeout settings as Linux. A `package-windows` job on pushes to `main` builds `cargo build --release -p app`, zips `app.exe`, `THIRD_PARTY_NOTICES.md` and `docs/windows.md` as `sketchup-alt-windows-x86_64.zip`, and uploads it as an artifact (no release, no signing). `THIRD_PARTY_NOTICES.md` gains the bundled fonts' licences (Inter and JetBrains Mono, SIL OFL 1.1 — copy the licence text shipped with the fonts if present in the repo, else name the licence and source).

## Review Focus

1. The named pipe must not be reachable by other local users or remote machines (security descriptor and `PIPE_REJECT_REMOTE_CLIENTS`), and a second instance must not hijack an existing name.
2. A path under `--api-root` given with a different case, a verbatim prefix, a UNC form, a junction or `..` segments must be judged the same as its canonical form; anything outside must stay refused.
3. Closing the window or `quit` must not leave a pipe server thread blocking exit.
4. The window launched from Explorer shows no console; launched from a terminal, `--headless --stdio` and `--mcp` still talk over stdin/stdout.
5. Clippy on the Windows target must be clean without blanket `allow`s.
