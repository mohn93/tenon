# M16c Component Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A personal library of components, materials and whole models kept as ordinary `.skr` files in a folder the user picks: save a selected component, a material or the whole model into it, browse it in a Library panel with thumbnails and search, insert an item (placed with the cursor like Paste, or a material added to the model), open an item to edit; commands and queries so agents can list, save and insert items.

**Architecture:** A library item is a `.skr` file. Items saved by the app carry one extra archive entry `library.json` (`{"kind": "component" | "material" | "model", "name": "..."}`); any other `.skr` in the folder is listed as a model named after its file. Session code (`session::library`) writes items (a component item is the selected instance's clip scene saved as a `.skr`: one root instance with its definitions, materials and tags; a material item is a scene holding only that material; a model item is the whole document), lists a folder safely (regular `.skr` files only, no links, bounded), and turns an item into a clip text with a fresh source token so inserting reuses the M16a paste path (definitions copied, materials and tags merged by name). The app keeps the folder in prefs, shows a Library dock tab with a search field and lazily rendered thumbnails (the M13d2 white-paper Snapshotter, iso view, cached in memory per path and modified time; materials use their swatch), and inserts through the Paste tool.

**Tech Stack:** Rust 2024, egui 0.36.2. No new dependencies.

**Spec:** `docs/superpowers/roadmap.md` row M16c.

## Global Constraints

- No new dependencies; `Cargo.lock` unchanged.
- Existing behaviour unchanged; `.skr` schema unchanged (the extra archive entry is ignored by readers that do not look for it; plain `.skr` files stay valid items).
- Library files are untrusted input: every read goes through the `.skr` reader's checks and the clip caps (M16a); listing never follows links and is bounded (at most 1000 items listed, names at most 256 characters).
- Agent paths go through `--api-root` checks (`ApiRoots::read`/`write`) like Open, Import, Export; new path-carrying commands get arms in `ApiRoots::apply`.
- New command variants get arms in `Document::execute`/`edit` and `session::batch::id_slots` (no `_` arm); new editor commands are listed in `EDITOR_COMMANDS` and its test.
- Gate per task (project rules in the SDD rules files): `cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace --lib --bins --tests`; Windows clippy runs in CI.
- Docs (`docs/agent-api.md`) updated in the task that changes behaviour. No emoji. Short commit messages. Never `git add -A`.

## Spec notes (rulings)

1. **Saving:** `save_to_library { path, kind: "component" | "material" | "model", item?: id, name?: string, overwrite?: bool }` (session command, not an undo step, does not change the model or its revision). `component`: `item` is an instance id `i<n>` of a component (a group is refused: "Make it a component first"); the file holds one instance of it at the origin (its placement's rotation and scale kept, translation removed). `material`: `item` is a material id; the file holds only that material (texture included). `model`: no `item`; the whole document. `name` defaults to the component's or material's name, or the file stem; stored in `library.json`. Path rules: `.skr` extension required; never the open model's own file; an existing file is replaced only with `overwrite`.
2. **Listing:** query `library { folder }` -> `[{ path, name, kind, modified }]` sorted by name (case-insensitive), at most 1000 (plus `more: true` when cut); regular `.skr` files directly in the folder (no recursion), no links, files over 256 MiB skipped; `kind`/`name` from `library.json` when present and valid, else `model` and the file stem; an unreadable entry is listed with `error`.
3. **Inserting:** `insert_library_item { path, at?: [f64;3] }` (session command, one undo step labelled `insert`): component or model -> the item's scene as a clip with a fresh source token (always new definitions; materials and tags merged by name), placed with its minimum bounding-box corner at `at`, or at the origin of the open context when `at` is absent; selects what was inserted. Material -> added to the model; if a material with that name exists and is identical it is reused, otherwise the new one is named "<name> 2", "<name> 3"... (lowest free); the material becomes the current paint material in the window (editor) and the outcome names its id.
4. **Window:** Settings > Files gains "Library folder" (Choose..., Clear). A Library dock tab (after Scenes): a search field (case-insensitive substring of the name), kind filter (All, Components, Materials, Models), a grid of tiles (thumbnail + name); click a component/model tile -> the Paste tool with that item (Esc cancels); click a material tile -> inserted and chosen as the paint material; right-click a tile -> Insert, Open (opens the item file as the document, settling unsaved changes first), Delete from Library (confirm; deletes the file only if it is a regular file in the folder). Saving: Entity Info / context of a selected component instance -> "Save to Library"; Materials panel -> "Save to Library" for the chosen material; File > Save Model to Library... All save actions ask for a name in a small sheet and write to `<folder>/<name>.skr` (name sanitized; existing name -> confirm overwrite). With no folder set the tab shows "Choose a library folder" with a button. The tab re-lists when shown, after a save/delete, and on window focus (no file watching).
5. **Thumbnails:** rendered lazily for visible tiles only, at most 2 per frame, 128x128, iso view fitted to the item, white paper (print mode), cached in memory by (path, modified time); materials use the swatch (colour or texture). Failures show a placeholder icon.
6. **Agents:** commands and query above; `insert_library_item` without `at` from an agent inserts at the origin (no tool). An editor command `place_library_item { path }` starts the Paste tool with the item in the window (like `paste_clipboard` without `at`).

## Review Focus

1. A component saved from a rotated, scaled instance inside an open group re-inserts with the same shape and size (rotation/scale kept, translation removed) and its materials and tags.
2. Inserting the same component item twice gives two separate definitions (fresh token each time); inserting into another model brings its materials and tags.
3. A library folder containing a symlink to a `.skr` elsewhere, a huge file, a non-`.skr` file, a damaged `.skr` and 2,000 files: listing skips/marks them correctly, stays bounded and fast, nothing panics.
4. Saving over an existing item without `overwrite` is refused; saving the open model's own file is refused; agent paths outside `--api-root` are refused for save, list and insert.
5. A material item with a texture inserted into a model that already has a different material of the same name gets "<name> 2" and keeps its texture.
