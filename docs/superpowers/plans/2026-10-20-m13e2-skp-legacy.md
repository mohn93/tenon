# M13e2 SketchUp Import (2017-2020 files) and Guides Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import and open SketchUp files saved by SketchUp 2017, 2018, 2019 and 2020 (the legacy MFC container) with the same fidelity as 2021+ files, and import guides from both containers.

**Architecture:** The vendored `skp` crate's legacy reader gains a topology output with the same shape the 2021+ path produces (`scene::Model` with `DefGeometry` per definition, plus a placement-free `SceneIndex`), so the session's existing `.skp` import maps both containers through one code path. The 2020 container's extra 16-byte block is handled by a version gate. Guides are added to `DefGeometry` for both containers. The legacy reader is hardened like the VFF path (element caps, no placement walks, checked arithmetic).

**Tech Stack:** Rust 2024 (the `skp` crate stays on edition 2021). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-10-tenon-design.md`, the M13e2 bullet; research in `docs/superpowers/research/2026-10-19-skp-readers.md`; the M13e1 plan `docs/superpowers/plans/2026-10-19-m13e1-skp-import.md` for the import mapping.

## Spec notes (rulings)

1. **2020 container:** `read_version_map` records the `CLayerManager` schema; when it is 7 or more (SketchUp 2020), the walk expects, right after the active-layer back-reference, the 16-byte block `00 00 00 ff fe ff 00` followed by nine zero bytes, and skips it before reading the definition count. If those bytes are not there, it falls back to openskp's retry (search the next 12 bytes for `ff fe ff 00`, skip zero padding in steps that keep 4-byte alignment, take the first count `0 < count <= limit` followed by a plausible list tag). The same fallback guards the root entity count and, for version 20, each definition's entity count, as openskp does.
2. **Topology output:** new `pub fn legacy::read_model(src: &dyn ByteSource, container: &Container, options: &ReadOptions) -> Result<(scene::Model, ReadStats)>` that fills `scene::Model { writer_version, is_vff: false, root, definitions, sections: default, bytes_read }` with one `DefGeometry` per definition (`Definition.pid` = its archive slot as `u64`, name, guid, `always_face_camera`), built before the arenas are released: vertices (inches), edges (`edge_v` rebased, `u32::MAX` for a missing end, flags in `edge_flag` bits, layer), faces in CSR form (`face_loop_ofs`, `loop_ofs`, `coedge_edge`, `coedge_reversed`), `face_normal`, `face_plane_d`, `face_material` and `face_back_material` (the back material is read, no longer dropped), `face_layer`, `face_flags` (bit 0 hidden; hidden faces are kept, not skipped), and `instances` as `RawInstance` (`m` from the record's 13 terms, `def_pid` the definition's slot, `material`, `layer`, `flags` with the hidden bit, `is_group` from the record's class, `is_image`). It never computes bounds, reachability or instance tables. `ReadOptions::max_elements` (M13e1) applies.
3. **Placement-free index:** `pub fn legacy::read_index(src, container) -> Result<SceneIndex>` gives materials (with textures as `TextureLocation::Inline { offset, len }` into the stream), layers and scenes without walking placements; it may share the parse with `read_model` (a single `read_model_and_index` returning both is fine).
4. **Guides:** `DefGeometry` gains `pub guides: Vec<RawGuide>` with `pub enum RawGuide { Line { point: [f64; 3], direction: [f64; 3] }, Point { position: [f64; 3] } }` (inches; finite infinite lines only: a line with start and end params is still imported as an infinite guide line through `point` along `direction`, matching our guides). Legacy: from the `ConstructionLine` and `ConstructionPoint` records the reader already parses. VFF: from the guide records in `model.dat` (layout taken from openskp's reader, credited in VENDORED.md); unknown guide record variants are skipped and counted. The session maps them to kernel guides (scaled like points); invalid ones are counted in the existing `skipped_guides` and warned.
5. **Root-list recovery:** when `read_entity_list` stops at an unknown back-reference or class reference, it resynchronises on the next recognisable entity tag within the list's byte span (bounded scan, at most 64 KiB per gap and 1,000 gaps per file) instead of abandoning the rest; entities it still cannot read count in `lost_entities`. If no safe recovery exists, keep the current stop. The truck model is the target: it must lose fewer entities than today, or the task reports why not.
6. **Deep nesting (barstools):** investigate the "implausible root entity count" with the 2017 copy; if a cause is found and fixed within this milestone, keep it; otherwise the import refuses with `invalid_input` "this SketchUp file could not be read (its component structure is not supported yet)". A refusal is acceptable; a wrong model is not.
7. **Hardening the legacy reader:** `walk` retries at most 4 candidate slot bases; total `resync_definition` scanning is capped at 64 MiB per file; burn-band arithmetic (`translate_ref`, `cum_delta`, loop offsets) uses checked arithmetic returning `Malformed`; `finish()`'s quadratic placement grouping is not on the import path (`read_model` does not call it).
8. **Session:** `read_skp` uses `legacy::read_model` and `legacy::read_index` for a legacy container instead of refusing; the legacy refusal message is removed (kept only for containers older than SketchUp 2017: header version below 17 gives `invalid_input` "SketchUp files older than 2017 are not supported"). Texture bytes for legacy materials are read from their inline offset and length within the stream (checked against `MAX_TEXTURE_BYTES` before reading). `ReadStats.lost_entities` and `faces_short_of_exact` become warnings ("N entities could not be read", ...); `notes` are not shown.
9. **Regression rule:** each legacy copy must import like its 2024 original: same number of definitions, instances, faces made (±0 for the cupboard fixtures; for the corpus, faces made within 1% and the same definitions and instances), materials, guides and model bounds within 1 mm. The corpus test (`#[ignore]`) runs all 24 models × 4 versions from `SKP_CORPUS/../legacy_out` against `legacy_src` and prints a table; the cupboard fixtures run in the normal suite.

## Review Focus

1. A legacy file must never import a different model silently: a definition count, root count or entity list misread must give an error or a counted loss, not geometry from the wrong records.
2. Hidden faces in legacy files are imported (visible, warned), as in 2021+ files; the couch must match its original's face count.
3. The 2020 gate must not misfire on 2017-2019 files (their bytes after the active layer differ).
4. Guides from both containers land at the same place as SketchUp shows them (the tutorial's 7 guide points, in the corpus).
5. A crafted legacy file cannot drive the resync scans, base retries or burn bands into unbounded work.
